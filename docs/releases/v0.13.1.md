# kasane-pdf v0.13.1

## Overview

0.13.1 is a security fix for `redact`, cut from v0.13.0. It contains no
other change.

- **Redaction**: a page whose content, forms or the appearances of the
  annotations it keeps draw an inline image (`BI … ID … EI`), or that shows a Type 3 glyph
  drawing one, is refused (`Error::Unsupported`), wherever the image
  lies; such an image away from the rects was kept. Readers do not all
  end inline image data where kasane does.

MSRV stays 1.92. No public signature changes (`cargo semver-checks`
against 0.13.0); the only behaviour change is the refusal above
([`api-stability.md`](../api-stability.md)).

## Security

- **Inline images read differently by pdf.js**
  ([GHSA-fqfv-cg5v-p7mr](https://github.com/akam1o/kasane-pdf/security/advisories/GHSA-fqfv-cg5v-p7mr),
  Low): `redact` kept an inline image away from the rects, reading its
  data as ending where its dictionary says or where the parser finds
  `EI`. pdf.js searches for `EI` with a heuristic: it can end the image
  inside its data, or run past the real end and resume at a later `EI`
  (in a string, a comment), and draw the bytes in between as content
  `redact` never read; content drawn so inside a rect stayed in the
  output while the redaction reported verified (0.6.0–0.13.0; a Type 3
  glyph's procedure from 0.7.0). MuPDF reads some of these constructions
  the same way. 0.13.1 refuses a page whose content, forms or the
  appearances of the annotations it keeps draw an inline image, or that shows a Type 3 glyph drawing
  one, wherever the image lies. The regression inputs are in
  `tests/redact_advisories.rs` (`fqfv-*`,
  [`advisory-regressions.md`](../security/advisory-regressions.md)).

## Compatibility

Pages with inline images that 0.13.0 redacted are now refused. Rendering,
text extraction, rewriting and the content editors are unchanged.
