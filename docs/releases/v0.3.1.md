# kasane-pdf v0.3.1

## Overview

A patch release with one fix: Type 1 fonts whose `FontMatrix` is not
the conventional `[0.001 0 0 0.001 0 0]` were drawn at the wrong scale
— and the page was reported as an exact render. No public item was
added, removed or changed (`cargo semver-checks` against 0.3.0: no
semver update required).

## Fix

- **Type 1 glyph outlines now go through the font program's own
  `FontMatrix`** (ISO 32000 §9.6.2: a Type 1 font program defines its
  glyph space; the PDF font dictionary does not repeat the matrix).
  - eexec programs (`/FontFile`): the matrix was looked up in the
    encrypted Private dictionary instead of the cleartext font
    dictionary where it belongs, so the default 0.001 was used.
  - CFF programs (`/FontFile3 /Type1C`): the matrix was not read;
    1000 units per em was assumed.
  - CID-keyed CFF (`CIDFontType0`): only the Top DICT x-scale was used;
    now the Font DICT matrix `FDSelect` assigns to each glyph, combined
    with the Top DICT matrix as FreeType combines them.

  A font in 2048 units came out about twice too large, glyphs
  overlapping. Shear and non-uniform matrices (oblique fonts) are now
  honoured instead of being reduced to a scale. Advances still come
  from `/Widths`; text-extraction glyph bounds and the redaction
  diagnosis use the same matrix. A `FontMatrix` that is present but not
  six finite numbers forming an invertible matrix is `Error::Structure`;
  an absent one is still 0.001.

## Behaviour change

Pixels change on pages that use such fonts — intended. On the 511-file
compatibility corpus exactly three files render differently, all three
the garbled pages this fixes (content SSIM against Poppler 0.07 → 0.88
and 0.04 → 0.71); every other page is unchanged, and no stage of any
file changes class. A font program with a malformed or singular
`FontMatrix`, previously drawn at 0.001, is now refused with
`Error::Structure`; none occurs in the corpus.

## Upgrading

```toml
[dependencies]
kasane-pdf = "0.3"
```

`cargo update -p kasane-pdf`. No source change is required.
