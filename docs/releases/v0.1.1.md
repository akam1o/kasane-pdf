# kasane-pdf v0.1.1

## Overview

A compatible maintenance release of the independent PDF engine:
every change is additive (`cargo semver-checks` against 0.1.0 reports
no semver update required), so updating from 0.1.0 needs no code
change. It adds a warning channel for non-conforming input the engine
can still process exactly, fixes a `/ToUnicode` parser gap, documents
the public API's stability contract, and records the dependency audit
that followed the `ttf-parser` maintenance notice.

## Highlights

- **Accepted with warnings.** A third outcome between a clean pass
  and a refusal: input that deviates from ISO 32000-1 in a way the
  engine can process *exactly* is accepted and recorded as a
  `Warning` on the `Document` (`take_warnings()`, `warnings()`,
  `warnings_dropped()`; the enum is `#[non_exhaustive]`). Two
  deviations qualify today: a `/FlateDecode` stream that ends after a
  sync-flush block without the final block and Adler-32 (every block
  was complete, so the output is exact; a stream cut inside a block is
  still refused), and a `bfchar`/`bfrange` entry of a `/ToUnicode`
  CMap that cannot be read (skipped; its codes stay unmapped, nothing
  is guessed). Strict mode is not weakened: the set is enumerated by
  the variants, and the CLI prints each warning on stderr.
- **`/ToUnicode` hex strings may contain white space** between digits
  (§7.3.4.3), which previously failed the whole CMap.
- **`kasane_pdf::Pixmap`** re-exports the `tiny-skia` type of
  `RenderedPage::pixmap` so it can be named without a second
  dependency.
- **Dependency audit.** `RUSTSEC-2026-0192` is an *unmaintained*
  notice for `ttf-parser`, not a vulnerability; the crate is kept for
  0.1.x with the comparison, the decision and the migration
  conditions in `docs/decisions/ttf-parser.md`. A RustSec audit job
  runs in CI and ignores only that informational id.
- **API stability contract.** `docs/api-stability.md` audits the
  published 0.1 surface and classifies every pending change as
  patch, minor or breaking, with the migration for the 0.2.0 items.
- **Examples and tests.** New examples `rewrite`, `recovery` and
  `cjk_fallback`; `tests/public_api.rs` exercises the public surface
  through public paths only; the README code blocks are doctests.

## Compatibility

On the 511-file corpus (427 files expected to be well-formed, every
page rendered): strict parse 404 → 406, render 365 → 368, text
381 → 384, rewrite 348 → 350, all four 315 → 318; no regressions;
43 adversarial files refused without crash or timeout; 385 rewritten
files reparse with an identical object graph and introduce no new
qpdf or Poppler diagnostic. Two of the passing files are accepted
with warnings and counted apart from a clean pass.

## Upgrading

```toml
[dependencies]
kasane-pdf = "0.1"
```

No source change is required. To see the new findings, read
`doc.take_warnings()` after an operation; match `Warning` with a
wildcard arm. Rust 1.92 or newer.

## Security

Signatures are detected, never verified; preserving the signed
`/ByteRange` is a structural property and says nothing about
cryptographic validity. Recovery mode is explicit and reports every
assumption. The `remove_*` editors are content editors, not
redaction. See `docs/security.md` and the README's *Security notes*.
