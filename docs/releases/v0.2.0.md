# kasane-pdf v0.2.0

## Overview

The API-stability release of the independent PDF engine. 0.2.0 makes,
once, the breaking changes that the 0.1 audit (`docs/api-stability.md`)
scheduled, so that later releases can add options, result fields and
error kinds without breaking callers. Engine behaviour on PDF input is
unchanged: the 511-file compatibility corpus renders, extracts and
rewrites identically to 0.1.1 in every stage class, SSIM value,
round-trip class and cause id. Every change is mechanical;
`docs/migration-0.2.md` gives the one-line replacement for each.

## Highlights

- **Errors you can classify.** `Error::kind()` returns the new
  `ErrorKind` enum (`as_str()` keeps the 0.1 strings, so CLI output is
  unchanged). Two new variants: `InvalidArgument` for a caller's bad
  option (an invalid DPI, a zero structural limit), and
  `SignaturePolicy { rule: SignatureRule, .. }` for an edit refused on
  a signature's declared terms — distinct from an unimplemented
  feature, and still never a claim that the signature is valid.
- **Options are built, not spelled out.** `Limits`, `RenderOptions`
  and the new `TextOptions` are `#[non_exhaustive]` with `with_*`
  builders and `validate()`; every entry point validates first.
  Fields stay readable and assignable. `extract_text` takes
  `&TextOptions` (`with_limits`, `with_hidden_content`,
  `with_region`); `extract_text_all` is gone.
- **A backend-neutral `RenderedPage`.** `width()`, `height()`,
  `stride()`, `pixel_format()`, `pixels()`, `into_rgba8()`, `to_png()`
  and the report accessors are the stable surface; the `tiny-skia`
  `Pixmap` is reachable only through the default feature
  `tiny-skia-interop`, so the rasteriser's major version is no longer
  part of the API.
- **`#[non_exhaustive]` everywhere it matters.** `Error`, `ErrorKind`,
  `Warning`, `SignatureRule`, `ChangeKind`, `ResolveKind`, `SubstKind`,
  `DestSource`, `TargetKind`, `PixelFormat`, and the option and result
  structs.

## Upgrading

```toml
[dependencies]
kasane-pdf = "0.2"
```

| 0.1 | 0.2 |
|---|---|
| `Limits { max_input_bytes: n, ..Limits::default() }` | `Limits::default().with_max_input_bytes(n)` |
| `RenderOptions { dpi: 144.0, ..Default::default() }` | `RenderOptions::default().with_dpi(144.0)` |
| `extract_text(&doc, page, &limits)` | `extract_text(&doc, page, &TextOptions::default().with_limits(limits))` |
| `rendered.pixmap`, `rendered.width` | `rendered.pixels()` / `rendered.pixmap()`, `rendered.width()` |
| `pixmap_to_png(&rendered.pixmap)` | `rendered.to_png()` |
| `e.kind() == "unsupported feature"` | `e.kind() == ErrorKind::Unsupported` |
| `Error::Unsupported { feature: "signed document", .. }` | `Error::SignaturePolicy { .. }` |

Rust 1.92 or newer. Features: `tiny-skia-interop` (default, on),
`cjk-fallback` (off).

## Compatibility

Measured on the same 511-file corpus as 0.1.1, every page: strict
parse 406, render 368, text 384, rewrite 350, all four 318 of the 427
files expected to be well-formed; 43 adversarial files refused without
crash or timeout; 385 rewritten files reparse with an identical object
graph and introduce no new qpdf or Poppler diagnostic. Two files are
accepted with warnings and counted apart from a clean pass.

## Security

Signatures are detected, never verified; `SignatureInfo` now says so
on every field, and a `SignaturePolicy` refusal is a structural rule,
not a validity verdict. Recovery mode is explicit and reports every
assumption. The `remove_*` editors are content editors, not
redaction. See `docs/security.md` and the README's *Security notes*.
