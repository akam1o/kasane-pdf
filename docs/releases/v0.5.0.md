# kasane-pdf v0.5.0

## Overview

0.5.0 is a rewrite release. `rewrite` now writes three kinds of
document it refused before — PDF 2.0, XFA forms and documents with
references to undefined objects — and a new entry point,
`rewrite_with`, takes explicit policies for what 0.4 could only refuse:
executable content can be **carried** (never executed) and usage-rights
signatures can be **removed**, each only on request and each stated in
a report the call returns.

Nothing changes for a caller who does not ask: `rewrite` keeps its
refusals, and `rewrite_with` with the default options produces exactly
`rewrite`'s bytes and errors (checked on every corpus document that
reaches the rewrite). No public item was removed or changed in
signature (`cargo semver-checks` against 0.4.1: no semver update
required); the additions are on `#[non_exhaustive]` types. The minor
version is for the behaviour changes below.

## Highlights

- **PDF 2.0 rewrite.** A document that declares 2.0 (header or catalog
  `/Version`) is written as 2.0 with the trailer `/ID` the standard
  requires (the input's permanent identifier, then a digest of the
  written body — deterministic). Page-level `/Metadata`, associated
  files (`/AF`, embedded files) and document parts (DPart) are carried
  with references renumbered and sharing kept. A version above 2.0 is
  still refused; 1.x output is unchanged and gets no `/ID`.
- **XFA forms carried.** The `/XFA` stream or packet array and
  `/NeedsRendering` are copied verbatim (names, order, duplicates,
  stream bytes). A packet holding an XML signature is refused like any
  signature; one that cannot be read completely to check is refused.
- **Undefined references** (§7.3.10) are written as references to
  `null` objects and reported (`Warning::UndefinedReference`) instead of
  failing the rewrite.
- **Explicit rewrite policies** — `rewrite_with(&Document,
  &RewriteOptions) -> Result<RewriteOutput, Error>`:
  - `ExecutableContentPolicy::Profile` (default): 0.4's behaviour, now
    reported; `Carry`: document-level scripts carried verbatim too;
    `RefuseScriptsAndExternal`: any script or external action anywhere
    refuses.
  - `UsageRightsPolicy::Refuse` (default) or `Remove`: Reader-extension
    (`/Perms /UR`, `/UR3`) signatures deleted, and only those.
- **An audit report, not a log line.** `RewriteOutput` holds the bytes
  and a `RewriteReport`: every action, multimedia annotation and XFA
  script carried (class, kind, owner, position, input and output
  object, script size, sharing — never script text, URLs or field
  names), structures that could not be classified, the version change,
  and what was done with usage-rights signatures
  (`UsageRightsOutcome::Removed(..)` lists each signature, the rights it
  granted, `/SigFlags` before and after, the input's revisions and what
  the output check verified). `Error::refusal_reason()` classifies every
  policy refusal without parsing messages.
- **Semantic verification.** The compatibility runner compares far
  more of a document's meaning across a rewrite (actions, scripts,
  XFA, metadata, viewer preferences, PDF 2.0 structures, multimedia,
  signatures) and accepts a difference only as a *declared*
  transformation (`transformed`, never counted as `pass`).

## API

```rust,no_run
use kasane_pdf::{
    rewrite_with, Document, ExecutableContentPolicy, RewriteOptions, UsageRightsOutcome,
    UsageRightsPolicy,
};

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let doc = Document::from_bytes(&std::fs::read("form.pdf")?)?;
    let opts = RewriteOptions::new()
        .with_executable_content(ExecutableContentPolicy::Carry)
        .with_usage_rights(UsageRightsPolicy::Remove);
    let out = rewrite_with(&doc, &opts)?; // Err: refused, nothing written
    if let UsageRightsOutcome::Removed(r) = out.report().usage_rights() {
        println!("removed {} usage-rights signature(s)", r.entries.len());
    }
    println!("{}", out.report()); // counts per class
    std::fs::write("out.pdf", out.bytes())?;
    Ok(())
}
```

New public items: `rewrite_with`, `RewriteOptions`, `RewriteOutput`,
`RewriteReport`, `ExecutableContentPolicy`, `MultimediaPolicy`,
`UsageRightsPolicy`, `ExecutableItem` and its parts (`ActionClass`,
`ActionKind`, `ActionOwner`, `Trigger`, `ScriptSize`),
`UnclassifiedStructure`, `UnclassifiedReason`, `VersionChange`,
`VersionReason`, `UsageRightsOutcome`, `UsageRightsRemoval`,
`RemovedSignature`, `SigFlagsChange`, `UsageRightsKey`,
`SubFilterKind`, `UsageRight`, `OutputCheck`, `RefusalReason`,
`Error::refusal_reason`, and `SignatureRule::{UsageRightsNotRemovable,
OtherSignaturePresent, SecurityStore, ResidualSignature}`. See
`docs/api-stability.md`. Examples: `examples/rewrite.rs`,
`examples/remove_usage_rights.rs`.

## Security

- **The default keeps 0.4's refusals.** `rewrite` and
  `rewrite_with(Default)` refuse signed documents (`/DocMDP`, `/UR`,
  `/UR3`, signed fields, XFA XML signatures), document-level scripts,
  `/RichMedia` and encrypted documents, as before.
- **Carry is not sanitizing.** `ExecutableContentPolicy::Carry` copies
  scripts and actions byte for byte. kasane-pdf never executes a
  script, but the output can do whatever the input could.
- **`RefuseScriptsAndExternal`** searches the whole document, not only
  the positions the report lists, for script and external actions.
- **Remove deletes usage-rights signatures and nothing else.**
  `UsageRightsPolicy::Remove` removes `/Perms /UR` and `/UR3`; the
  extended rights they grant in a reader are withdrawn. It does not
  verify any signature and does not re-sign.
  - Any other signature refuses the whole rewrite: certification
    (`/DocMDP`), approval and timestamp signatures, XFA XML
    signatures, `/DSS`, `/Legal`, a field `/Lock`, or any dictionary
    with a signature marker anywhere reachable — found by structure,
    never by names.
  - A usage-rights signature that cannot be confirmed as one, or is
    referenced from anywhere but `/Perms`, refuses; so does a document
    that cannot be read or searched completely.
  - The output is parsed again and checked by walkers of its own before
    it is returned; a failed check returns an error and no bytes.
  - The removal is in the report's type
    (`RewriteReport::usage_rights()`). `RewriteOutput` is `#[must_use]`,
    but that alone does not make a caller read the report.
- Reports and errors hold positions, kinds, object numbers and lengths,
  never signature values, certificates, script text or field names.

## Behaviour changes

- `rewrite` writes PDF 2.0 documents, XFA forms and documents with
  undefined references, which 0.4.1 refused (see *Highlights*).
- `rewrite`'s refusal checks now follow a compressed object whose value
  is a reference: a `/Perms /UR3` behind one was rewritten by 0.4.1 and
  is now refused.
- `max_output_bytes` covers the whole written file, the trailer
  included.
- `audit_residuals` reaches every link of a reference chain (links
  were reported as unreachable objects).

## Known limitations

- **Remove costs memory and time.** Its output check reparses the
  output (a second document in memory) and walks it. Linear and bounded
  by the limits; on the corpus at most +0.23 s per file. On a 27 MB
  worst-case catalog, peak memory is about 2–3× and time about 10× the
  plain rewrite's (2.9 GB, 2.9 s against 1.4 GB, 0.25 s).
- **Usage-rights forms usually need Carry too.** The 27 Reader-extended
  forms in the corpus all hold a document-level script, so `Remove`
  alone rewrites none of them; `Carry` + `Remove` rewrites all 27.
- **Multimedia** (`/RichMedia`) is refused under every policy; there is
  no carry policy for it yet.
- **Corpus scope.** The figures below are for a 511-file corpus of real
  and test documents; Reader-extended forms in it come from one
  publisher. Other producers may build usage-rights signatures
  differently (`Remove` refuses what it cannot confirm).
- **Not in this release** (planned robustness work, deferred): a lower
  memory bound for very large soft masks (one corpus page reaches
  1.3 GB), a default `max_xobject_depth` derived from a stack measurement
  (one corpus document needs nesting 33–48; raise the limit to read
  it), a 32-bit arithmetic audit with a 32-bit CI job, a structured
  content-stream fuzz target with a nightly fuzz job, and more recovery
  rules. 0.5.0 behaves as 0.4.1 in each of these.
- Parse, render and text limitations of 0.4 are unchanged
  (`docs/limitations.md`).
- **Linux and macOS** give the same results except the anti-aliased
  ink of a few pages (at most 0.064 % of a page's pixels), which
  changes one round-trip comparison per configuration.

## Verification

- Compatibility corpus, 511 files, `expect: pass` (425), macOS
  (nightly configuration, Poppler witness):

  | | default | Carry | Remove | Carry + Remove |
  |---|---:|---:|---:|---:|
  | Full PASS (parse, render, text, rewrite) | **345** | 351 | 345 | 378 |
  | rewrite (all files) | 436 | 444 | 436 | 471 |
  | full round trip (declared included) | 433 | 441 | 433 | 468 |
  | semantic pass / fail | 302 / 0 | 310 / 0 | 302 / 0 | 337 / 0 |

  0.4.1: Full PASS 339. The default figure is the release's: the
  option columns are what a caller gets by asking for them. Strict
  parse 408, render 380, text 392, 44 / 44 adversarial files refused,
  no crash or timeout. `rewrite_with(Default)` is byte-identical to
  `rewrite` on all 487 documents that reach the rewrite. Each of the 27
  usage-rights removals was checked by the library, the runner's own
  reading, `qpdf --check` and a qpdf object dump, and pypdf: no
  signature marker or `/ByteRange` left, pages, render and text kept.
- The Linux x86_64 nightly on the integrated code agrees (default and
  `Carry`; full round trip 432 / 440, the ink difference above).
- The plan's provisional default target (≥ 348) is not met: every
  remaining default refusal of an otherwise passing document is a
  policy refusal (27 usage-rights signatures, 6 document-level scripts,
  2 encrypted), reached only through the options; see
  `docs/plans/v0.5.0.md` §24.
- Fuzzing: the new targets `rewrite_graph`, `rewrite_policy` and
  `signature_markers`, plus the existing ones; no crash, timeout or OOM
  on the release code.
- Independent reviews of every series; their P0 / P1 findings fixed
  with regression tests.
