# kasane-pdf v0.3.0

## Overview

kasane-pdf now **reads encrypted documents** protected by the Standard
security handler — revisions 2 to 6, RC4, AES-128 and AES-256 — with
the empty, a user or an owner password. It does **not write**
encrypted documents.

No public item was removed or changed in signature (`cargo
semver-checks` against 0.2.2: no semver update required). The minor
version is for what callers observe: files that 0.2 refused with
`Error::Encrypted` now open, and that error's meaning narrows. Read
[`docs/migration-0.3.md`](../migration-0.3.md) if you relied on it.

## Highlights

- **Standard security handler** (ISO 32000-2 §7.6): revisions 2–6;
  RC4 40–128-bit, AES-128 (`/AESV2`), AES-256 (`/AESV3`, R5 and R6 with
  Algorithm 2.B and the `/Perms` integrity check); crypt filters
  (`/StmF`, `/StrF`, `/EFF`, `/Identity`, the `/Crypt` stream filter);
  `/EncryptMetadata false`; unencrypted cross-reference streams and
  signature `/Contents`; object streams; incremental updates.
- **Passwords**: `Document::open(&data, &OpenOptions::new().with_password(..))`,
  tried as user then owner password. Unicode passwords follow the
  revision's encoding — SASLprep for R5/R6 (truncated to 127 bytes),
  PDFDocEncoding for R2–R4. Passwords and keys are held in zeroed
  buffers and never appear in `Debug`, errors or warnings.
- **`doc.encryption()`** reports the revision, methods, key length,
  which password opened the file, whether the user password is empty,
  and the `/P` permission bits.
- **CLI**: `--password-file <path>` (or `-` for standard input) on every
  subcommand. There is deliberately no `--password <text>`.
- **Typed errors**: wrong password `Encrypted`; malformed `/Encrypt`
  dictionary `Structure` (never a guessed default that would skip
  decryption); unimplemented handler or method `Unsupported`.
- **Text extraction fix**: a non-embedded Standard 14 font without
  `/Encoding` now resolves through its built-in encoding instead of
  reporting every code unresolved.

## What encryption does not mean

- **Permissions are not access control.** `/P` is the author's request
  to a conforming reader; kasane-pdf reports it and enforces nothing.
  Anyone who can open the file can read all of it.
- **An empty user password gives no confidentiality** — check
  `EncryptionInfo::empty_user_password`.
- **Reading an encrypted file says nothing about its protection.**
  Revisions 2–4 rely on RC4 and MD5; only R6 with a strong password is
  meaningful protection.

## Behaviour changes

| input | 0.2.2 | 0.3.0 |
|---|---|---|
| encrypted, opens with the empty user password | `Encrypted` | **opened** |
| encrypted, wrong or missing password | `Encrypted` | `Encrypted` |
| malformed `/Encrypt` dictionary | `Encrypted` | `Structure` |
| public-key / third-party handler, unknown revision or crypt-filter method | `Encrypted` | `Unsupported` |
| damaged encrypted file, recovery mode | `Encrypted` | `Unsupported` (the table of an encrypted file is never rebuilt) |
| R4 key under 128 bits that only Acrobat's zero-padding decrypts | `Encrypted` | strict: `Unsupported`; recovery: opened, `RecoveryRule::PaddedShortEncryptionKey` |
| `rewrite` / `Edit::rewrite` / `save_incremental` of an encrypted document | (could not be opened) | `Unsupported { feature: "writing an encrypted document" }` |

## Verification

- Known-answer tests: the file key of twelve fixtures (R2–R6, Unicode
  passwords) equals qpdf's; Poppler extracts the same text from every
  fixture; an independent Python implementation writes the short-key
  and incremental fixtures (checked with pypdf).
- An independent review by a second model (one high finding, fixed
  before this release) and a final audit (three P1 and four P2 findings
  fixed — malformed crypt-filter entries no longer default to
  unencrypted); details in [`docs/plans/encryption.md`](../plans/encryption.md).
- Fuzzing: three cargo-fuzz targets on the encrypted paths, four
  campaigns, about 12.5 million executions; the final campaign found
  nothing.
- Compatibility corpus (511 files, 427 expected to be well-formed):
  strict render 378 → **379** of 427, of which approximate 69; recovered
  18 → **19**; text 390 → **391**; full PASS 325; round trip 411; no
  file lost a stage; Poppler SSIM dropped on no file; 43 adversarial
  files refused, no crash or timeout. Of the six encrypted corpus files
  three open and render strictly, two need a password (correctly
  refused), one needs Acrobat's short-key padding (recovered).

## Not in this release

- Writing encrypted documents, including an incremental save that keeps
  the encryption.
- Public-key (`/Adobe.PubSec`) and third-party security handlers.
- Rebuilding the cross-reference table of a damaged encrypted file.
- The distribution-safe redaction API (a design memo only).

## Upgrading

```toml
[dependencies]
kasane-pdf = "0.3"
```

New dependencies: RustCrypto `aes`, `cbc`, `rc4`, `md-5`, `sha2`,
`zeroize`, and `stringprep` — pure Rust, MIT/Apache-2.0 (plus
Unicode-3.0 for `unicode-normalization`'s tables), WASM-clean. MSRV
unchanged (1.92).
