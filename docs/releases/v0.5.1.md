# kasane-pdf v0.5.1

## Overview

0.5.1 is a rendering-robustness release with a security fix. It
raises the default nesting depth for forms from a stack measurement,
adds structured render fuzzing that runs on every pull request and
every night, and fixes what that fuzzing found: two panics on extreme
geometry, unbounded clip-mask memory, and dashed strokes that could
take minutes to render.

No public API changes (`cargo semver-checks` against 0.5.0: no semver
update required). Upgrading is recommended for every application that
renders documents it does not control (Security, below).

## Highlights

- **Deeper nesting by default.** `max_xobject_depth` is 48 (was 32),
  chosen from the stack each nesting path needs, measured on macOS
  arm64 and Linux x86_64. The one corpus document nested deeper than 32
  (`mlp-mixer`, 33–48 levels) now renders all 48 pages.
- **Structured render fuzzing.** Two new targets generate valid pages
  and object graphs instead of random bytes, so they reach the
  interpreter's deep paths. They run as a smoke test on every pull
  request and for 15 minutes per target every night.
- **Fixes from that fuzzing:** a dashed-stroke slowdown (Security),
  panics on extreme line widths and coordinates, and clip-mask copies
  that could demand gigabytes.

## Rendering robustness

- **Nesting depth.** Forms, transparency groups, soft-mask groups,
  annotation appearances and Type 3 glyphs nest at most 48 levels by
  default; deeper is `Error::LimitExceeded { limit:
  "max_xobject_depth" }`, and a form that invokes itself is
  `Error::CycleDetected`. The interpreter now dispatches the operators
  that re-enter it from a small stack frame, so 48 levels need less
  stack than 32 did in 0.5.0: at most ≈ 1.2 MiB in a debug build and
  ≈ 0.25 MiB in release (the costliest path, a soft mask's group),
  within a 2 MiB thread. Tiling patterns keep their fixed 8 levels.
- **Clip masks.** A saved graphics state (`q`, a form, a group, a
  pattern cell) shares its clip and soft masks instead of copying them;
  a clip that cuts nothing away keeps the current mask. The masks alive
  at once are bounded by `max_render_buffer_bytes`, an allowance of
  their own beside the page and its layers. In 0.5.0 a few bytes of
  content (`re W n` and 1000 `q`) cost 2.2 GB at 600 dpi on a 600 pt
  page; now 119 MB.
- **Extreme geometry.** A stroke wider than 2^24 device pixels, or a
  path reaching beyond ±2^24 device pixels, panicked inside the
  rasteriser in every earlier release. Such a stroke is now narrowed
  when that keeps its coverage (straight segments, round joins or
  miters within their limit), such a path is skipped when it lies
  entirely off the page, and anything else is refused with
  `Error::Unsupported` ("stroke width", "geometry extent").

## Security

**Dashed strokes could take minutes to render.**

- *What:* round or square line caps on a dash pattern along a long
  path made the rasteriser's work grow with the square of the path
  edges crossing each pixel row. A 15 KB content stream took 63 s to
  render in 0.5.0 at line width 100 and over 170 s at width 600
  (release build, default settings, a 600 pt page at 72 dpi); higher
  resolutions take longer.
- *Affected:* rendering (`render_page`, and the CLI's `render`) of
  attacker-controlled page content, at default settings. Text
  extraction does not rasterise and is not affected. Measured on
  0.5.0; the code path is present in every release from 0.1.0.
- *Impact:* CPU time only — the work is finite and its memory is
  bounded by the existing limits. An application that renders
  untrusted documents on demand can be kept busy for minutes per page.
- *Fixed in 0.5.1:* a dashed stroke's work is estimated before it is
  drawn, per stroke and summed over the page; a stroke over a bound is
  refused with `Error::Unsupported { feature: "dashed stroke" }`, and
  the rest of the page is not rendered (as for any refusal). Dashed
  strokes within the bound draw exactly as before. The input above is
  refused in milliseconds.
- *What it does not do:* the bound is on estimated work, not on time.
  Dashed strokes inside it have been measured at up to a few seconds,
  and rendering time in general is not bounded by `Limits` (below).
- *Recommendation:* upgrade. With or without it, render untrusted
  documents under an application time limit (a worker thread or
  process that can be abandoned), and tighten `Limits` and the DPI to
  what the application needs (`docs/security.md`).

The description of this issue and its reproduction have been public in
the repository since the fix was merged (2026-11-05).

## Behaviour changes

On the 511-file compatibility corpus one document changes (it renders
now); every other renders, extracts and rewrites identically. The
changes are on extreme or hostile input:

- **More nesting renders:** documents nested 33–48 levels deep render
  instead of `LimitExceeded` (also in `diagnose_redaction`,
  `remove_region` and `remove_image_region`). A limit set by the caller
  is unchanged.
- **New refusals**, all `Error::Unsupported`: "dashed stroke" (above),
  "stroke width" and "geometry extent" (both replace panics).
- **Mask memory:** many distinct nested clips at a high resolution can
  now be `LimitExceeded` (`max_render_buffer_bytes`) where 0.5.0 used
  the memory — e.g. 32 nested forms with ever smaller BBoxes at
  600 dpi, which 0.5.0 drew with ≈ 0.9 GB.
- `rewrite`, `rewrite_with` and `rewrite_with_limits` are unchanged:
  `rewrite_with` with the default options gives `rewrite`'s bytes on
  487 of 487 corpus documents it writes.

## API compatibility

No public item is added, removed or changed. `Limits::default()`
changes one value (`max_xobject_depth` 32 → 48). The new refusals use
existing `Error` variants. `cargo semver-checks check-release
--baseline-version 0.5.0 --release-type patch`: no semver update
required. MSRV stays 1.92.

## Testing and fuzzing

- **Targets** (`fuzz/README.md`): `render_content` — a valid page
  holding every resource kind the renderer draws, its content stream
  generated from the input, with oracles for determinism, `q … Q`
  wrapping, an identity `cm` and shared-versus-copied forms;
  `render_graph` — page trees and form graphs with sharing, cycles,
  soft masks, tiling patterns, broken references and object streams,
  rendered strict and in recovery mode. Synthetic seeds are committed
  (no document content).
- **Pull requests:** the seeds replayed with a check that their pages
  paint, then 3000 new inputs per target; a Linux job runs the
  depth and stack tests in debug and release builds.
- **Nightly** (`fuzz-nightly.yml`, its own workflow, `contents: read`
  only): 15 minutes per target with the corpus kept in the Actions
  cache. A crash, a timeout (30 s per input) or an out-of-memory
  (2 GiB) fails the job and keeps the input for 14 days; a self-test
  makes sure each of the three is detected. Verified on GitHub Actions
  on dispatch and on its daily schedule.
- **Stack:** the depth boundary (47 and 48 render, 49 is refused) on
  every nesting path, cycles, the state after a refusal, and the
  default depth in a 2 MiB / 512 KiB thread, each in a child process
  so an overflow cannot take down the test run; the measured stack per
  path is printed on Linux in CI.

## Known limitations

- **Rendering time is not bounded.** `Limits` caps sizes, counts and
  depths, not elapsed time; a page within every limit can still take
  minutes to render. The dashed-stroke fix removes one amplification,
  not the class. Render untrusted documents under an application time
  limit (`docs/security.md`).
- **Recursion uses the native stack.** The default depth fits a 2 MiB
  thread; a caller who raises `max_xobject_depth` needs ≈ 25 KiB
  (debug) / 5 KiB (release) more per level. Measured with glibc and
  the Rust standard library's threads on Linux x86_64 and macOS arm64;
  musl and custom stacks are not measured.
- **Memory.** The page, its layers and the clip masks are each bounded
  by `max_render_buffer_bytes`, so a page can hold about twice that. A
  very large 1-bit soft mask is still expanded at full resolution for
  each use (one corpus page reaches 1.3 GB; planned).
- **Fuzzing scope.** The render targets do not cover TrueType, CFF or
  CID fonts, mesh shadings, images behind filters or optional content.
  The pull-request smoke's exploration is bounded but not
  bit-reproducible (the inputs it reaches can vary between runs; each
  input's result is deterministic).
- **Corpus scope.** The figures are from macOS; the full corpus was
  not measured on Linux for this release.
- A stroke in a pattern colour is drawn without its dash pattern
  (since 0.1).
- **Not in this release** (planned): the soft-mask memory bound, a
  32-bit arithmetic audit, more recovery rules.
- Parse, render, text and rewrite limitations of 0.5.0 are unchanged
  (`docs/limitations.md`).

## Upgrade notes

- No code changes are needed.
- If you set `max_xobject_depth` yourself, nothing changes. If you rely
  on the default and run rendering on small thread stacks, check them
  against the figures above.
- New `Error::Unsupported` features may appear on extreme input:
  "dashed stroke", "stroke width", "geometry extent". Handle them like
  any other refusal of a page.
- If you render untrusted documents, add an application time limit if
  you do not have one.
