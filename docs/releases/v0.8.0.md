# kasane-pdf v0.8.0

## Overview

0.8.0 lets `redact` keep a document's structure tree: instead of
refusing a tree with alternate text, it removes the text of the
elements whose content the rects touch and keeps the rest, so the
output stays tagged. It also reports the data it carries without
reading it (attachments, metadata, unknown streams …), with an opt-in
mode that refuses such output, and reads Type 0 CMaps as Poppler, MuPDF
and pdf.js were measured to — refusing the codes and CMap constructions
they were found to disagree on. Soft-masked, Separation and
DeviceN images are now redacted, and annotations without an appearance
stream are taken where readers draw them.

MSRV stays 1.92. The release is breaking only in that `Diagnosis`
gains a field and becomes `#[non_exhaustive]` (see Compatibility).
Upgrading is recommended for every application that uses `redact`.

## Security

Two advisories, both fixed here; upgrading is recommended for every
application that uses `redact`.

### Removed data kept through other references ([GHSA-cjhc-76x8-crrq](https://github.com/akam1o/kasane-pdf/security/advisories/GHSA-cjhc-76x8-crrq), Medium)

- *What:* `redact` writes only what the output refers to and verified only
  edited images' and forms' originals. When something else referred to an
  object it replaced or removed whole — a catalog or page entry no structure
  names, `/PieceInfo`, an embedded file's `/EF`, a structure element's
  `/MCR /Stm` — that object was written out unchanged: an edited page's
  original content stream (everything the rectangles removed), a removed
  link's appearance and what it draws (images, masks, patterns, soft mask
  groups), a removed annotation's dictionary as a stream's dictionary, a
  removed Type 3 glyph's procedure, the font's former `/ToUnicode`. No
  reader draws them on the page; any parser reads them.
- *Affected:* `redact` 0.6.0–0.7.0 (some routes 0.7.0 only).
- *Fixed:* verification fails on any such copy (by digest; allowed only
  where the output still draws or uses the same bytes); removing an
  annotation whose appearance draws through patterns, shadings, soft mask
  groups or Type 3 fonts, or through resources it does not have itself, is
  refused; a structure `/MCR /Stm` to the original content leaves the tree.

### Readers disagreeing on CMaps ([GHSA-3f9j-35f2-6659](https://github.com/akam1o/kasane-pdf/security/advisories/GHSA-3f9j-35f2-6659), Low)

- *What:* when a Type 0 font's embedded CMap defines a code by
  `begincidchar` and again, with another CID, by a later `begincidrange`,
  Poppler, MuPDF and pdf.js take the later definition; kasane-pdf took the
  `cidchar`. It also matched `cidchar` entries by value whatever their
  length, where Poppler matches bytes. The glyph widths, and so where the
  following glyphs fall, then differed: `redact` could keep glyphs those
  readers draw inside the rect.
- *Affected:* `redact` 0.6.0–0.7.0.
- *Also:* other constructions read differently — bf mappings in an
  encoding CMap, definitions after `endcmap`, codes passed through an
  Identity base, `/WMode` other than 0 or 1, odd-length hex codes, stray
  tokens, codespace ranges of different lengths sharing leading bytes.
- *Fixed:* the latest definition wins, matched by code length; `redact`
  refuses a code whose value another length maps to another CID (and
  codes only a notdef mapping or nothing maps), and text in a CMap with
  any of the other constructions.

## Added

- **Structure tree editing** (by default): every element the tree's
  references tie to content the edit touches — matched by marked-content `MCID` through `/K`,
  `/ParentTree`, `/IDTree`, `/MCR` and `/OBJR` — and its ancestors lose
  `/Alt`, `/ActualText`, `/E`, `/T`, `/Phoneme`, `/AF` and the strings of
  their attribute objects (`/A`, `/ClassMap` classes); references to
  removed annotations and edited originals leave `/K`; a removed
  annotation's `/ParentTree` entry goes. Untouched elements keep
  everything. Cycles, kids of unknown kinds and touched elements written
  inside other objects are refused; verification re-reads the output's
  tree. `Redaction::{structure_texts_removed, structure_items_removed}`.
  `remove_structure_tree(true)` still removes the whole tree. Tagged
  links and annotations removed with a rect no longer refuse.
- **Uninspected data**: `uninspected_data(&Document, &Limits) ->
  DataInventory` (`DataItem`, `DataRole`, `DataStatus`) classifies every
  stream by the role it is reached in — searched for copies of the
  removed text, interpreted, uninspected (listed with object, role,
  path, length and filters), not carried. `Diagnosis::data`,
  `Redaction::uninspected`; `preflight-redaction` and `redact` print it.
- **Strict mode**: `RedactOptions::refuse_uninspected` (CLI
  `--refuse-uninspected`) refuses an output that carries uninspected
  data or whose inventory a limit stopped. It narrows a success to
  "every stream carried is reached in a role whose format `redact` reads
  or interprets" (the role, not the use, is classified: an unused font
  or pattern counts as interpreted); it is not a proof that no copy of
  the removed content remains.
- **Type 0 CMaps**: notdef mappings (`beginnotdefchar`,
  `beginnotdefrange`) are honoured in rendering, extraction and
  redaction.
- `redact` edits images with a soft mask (8-bit DeviceGray; its samples
  inside the rects are made opaque in a copy) and Separation and DeviceN
  images, and removes the thumbnail (`/Thumb`) of every edited page
  (`Redaction::thumbnails_removed`).

## Behaviour changes

- `redact` refuses text in a CMap with constructions readers read
  differently (bf mappings in an encoding CMap, definitions after
  `endcmap`, codes an embedded CMap passes through an Identity base (`usecmap` Identity) rather than listing them, a `/WMode` other
  than 0 or 1 or defined twice, odd-length hex codes, stray tokens,
  codespace ranges of different lengths sharing leading bytes), and text
  showing a Type 0 code that readers map differently: one only a notdef mapping or nothing maps, bytes in no
  codespace range, or a value another code length maps to another CID
  (Poppler, MuPDF and pdf.js draw such codes with different glyphs and
  widths). Fonts that only declare such mappings still redact.
- A code defined by both `cidchar` and `cidrange` takes the later
  definition, matched by code length, as Poppler, MuPDF and pdf.js read
  it (the `cidchar` won before).
- Removing an annotation whose appearance draws through patterns,
  shadings, soft mask groups or Type 3 fonts, or names resources it does
  not have, is refused (what those hold would not be checked).
- An annotation without an appearance stream is tested where readers
  draw it — its `/Rect` and its geometry, each grown by its border and
  decorations (line endings, leader lines, a text markup's rounded ends)
  — instead of being refused when its geometry left `/Rect`; one with a
  caption or a cloudy border is refused.
- The diagnosis lists a soft mask among an image's blockers only when
  `redact` cannot edit it.
- Verification also fails when the output holds, whatever refers to it,
  an edited page's original content stream (other than as a page's
  `/Contents`), a removed link's appearance, the masks of removed images,
  a removed Type 3 glyph's procedure or the font's former `/ToUnicode`, a
  removed annotation's dictionary as a stream's dictionary, or an edited
  page's thumbnail; a document referring to one from elsewhere is
  refused.

central block on page 1):

| the same with `--remove-javascript` | 80 | 91 |
| the same with `--refuse-uninspected` | — | 87 |

No word or character kept outside the rects was lost beyond 0.7.0's
counts. The two runs reported `unexpected` are the known false signal
(zeroed image samples that were already black); the evaluation now
checks it mechanically. Timing (`scripts/bench-redact.py`, best of
5) is 0–21 % above 0.7.0: equal on large text and nested forms, the most
on many resources or font dictionaries (the added structure, inventory
and verification work).

## Compatibility

- `Diagnosis` gains `data` and is now `#[non_exhaustive]`: a struct
  literal of it no longer compiles (it is a result; read its fields).
  `cargo semver-checks` against 0.7.0 reports only that.
- Documents with a structure tree carrying alternate text, and tagged
  annotations removed with a rect, now redact instead of refusing (pass
  `remove_structure_tree(true)` for the former behaviour of dropping the
  tree).
- Some Type 0 text that redacted before is now refused (codes readers
  map differently); its glyphs could be placed differently by readers.

## Known limitations

`redact` stays positional and refuses what it cannot remove exactly
(the full list: `docs/features/redaction.md`, `docs/limitations.md`).
Notably:

- Structure elements are not split: an element across a rect loses the
  accessibility text of its kept part too. Content outside every
  marked-content sequence relates to no element, and its tree text is
  kept (copies of removed text there are reported in `elsewhere`).
- The strict mode does not search interpreted data (text in an image's
  pixels or a font program) and makes no byte search.
- Refused: shadings and tiling patterns crossing a rect, curved fills
  crossing a rect, widgets and other non-markup annotations meeting a
  rect, XFA forms with `remove_javascript`, signed or encrypted
  documents, images other than 8-bit (and soft masks other than 8-bit
  DeviceGray), non-embedded fonts other than the Latin Standard 14 with
  `embed_substitute_fonts`.
