# kasane-pdf v0.2.2

## Overview

A patch release with one fix: a panic reachable from any input. No
public item was added, removed or changed (`cargo semver-checks`
against 0.2.1 reports no semver update required). Upgrading is
recommended for every user of 0.1.0 – 0.2.1 that parses untrusted
files.

## Fix

- **Panic on an empty stream without a usable `/Length`.** When a
  stream's `/Length` is absent, not an integer, or inconsistent with
  the file, the parser scans for `endstream` and removes the end-of-line
  marker in front of it (§7.3.8.1). In an empty stream
  (`stream⏎endstream`) that marker is the one ending the `stream`
  keyword line, so the computed end of the data fell one byte before
  its start and slicing the input panicked. The input needs no other
  property: the panic was reachable in strict and recovery mode, from
  `Document::from_bytes`, `Document::from_bytes_recovering` and every
  operation that resolves such a stream. The back-off now never passes
  the start of the data; such a stream is empty.

  Found by fuzzing (cargo-fuzz, libFuzzer with AddressSanitizer);
  present since 0.1.0. Regression test: `tests/parse_stream_length.rs`
  (LF and CRLF line ends, an inconsistent `/Length`, a blank line, a
  one-line stream).

## Security

A process that parses untrusted PDFs without `catch_unwind` could be
terminated by a small crafted file (denial of service). No memory
safety issue is involved — the panic is Rust's bounds check. No other
behaviour changes: on the 511-file compatibility corpus every stage of
every file classifies identically to 0.2.1.

## Upgrading

```toml
[dependencies]
kasane-pdf = "0.2"
```

`cargo update -p kasane-pdf`. No source change is required.
