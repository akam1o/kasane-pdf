# kasane-pdf v0.4.1

## Overview

A patch release that fixes how the cross-reference data of
incrementally updated files is read. kasane-pdf could read an object
from an older revision of a file instead of the current one, resolve an
object the current revision had deleted, or fail to resolve an object
stored at a generation above 0. No public item was added, removed or
changed (`cargo semver-checks` against 0.4.0: no semver update
required).

## Fixes

The rule (ISO 32000-1 §7.5.4, §7.5.6, §7.5.8; ISO 32000-2 §7.5.8.4 as
clarified by PDF Association issue #237): for each object number, the
newest update section that lists the number decides — in use at a
generation, compressed, or free — and older sections never override it.
Within a hybrid-reference section the classic table is searched first;
its `/XRefStm` stream supplies only the numbers the table does not
list. A reference `n g R` resolves only when the deciding entry is in
use at generation `g`; otherwise it is a reference to the null object
(§7.3.10).

1. **Updates appended to hybrid-reference files were ignored.** An
   older section's `/XRefStm` stream overrode the newer sections, so
   every object that stream listed was read from the old revision —
   files written as hybrid-reference files (as some office suites do)
   and later updated incrementally (form filling, annotations,
   signatures) were read as they were before the update.
2. **Newer entries were overwritten by older ones** in that case — the
   same defect seen from the update's side: an object the update
   changed kept its old body.
3. **Deleted objects could still be resolved.** Deleting an object
   writes a free entry with the next generation number (§7.5.4); the
   older in-use entry stayed reachable, so a remaining reference
   resolved to the deleted body.
4. **Objects at a generation above 0 in cross-reference streams did
   not resolve.** The generation of a type 1 entry (field 3) was
   dropped, so `n g R` with `g > 0` was treated as undefined (null).
5. **Range checks.** Generations above 65535 on in-use entries and
   object-stream numbers or indices above 2³²−1 are refused instead of
   being truncated onto another object; offsets are checked before
   conversion, so a 32-bit (wasm32) build cannot wrap an offset past
   4 GiB onto an unrelated position. `/XRefStm` must point at a
   cross-reference stream and is honoured only in classic trailers;
   within a hybrid section the table's entry now precedes the stream's
   (qpdf, Poppler and macOS Quartz agree).

Affected operations: opening a document and resolving its objects —
and so everything built on them: rendering, text extraction,
`rewrite` (which writes the current view of the file as a single
revision), `Edit::save_incremental` (after a hybrid-reference section
kasane-pdf did not read back the edit it had just written), the
residual audit and the redaction diagnosis.

## Behaviour change

Documents now read as qpdf, Poppler and Quartz read them in every case
where the specification leaves no choice. Two cases follow the
specification and qpdf where Poppler and Quartz differ: an object freed
by a newer section stays deleted, and a number a hybrid section's table
lists as free is not taken from that section's own stream. On the
511-file compatibility corpus three documents change, each verified
object by object against qpdf: one hybrid-reference file whose update
is now read, two files whose cross-reference streams declare
generations above 0 (one of which can now be rewritten); no document is
newly refused. In-use generations above 65535 and an `/XRefStm` that
does not point at a cross-reference stream are now refused
(`Error::Parse` / `Error::Structure`); recovery mode
(`Document::from_bytes_recovering`) is unchanged.

## Security note

These were defects in interpreting a file's update history: kasane-pdf
could see different content than other PDF readers see in the same
file, and `rewrite` could write an older or a deleted object as current
content. That can lead to unintended disclosure — content a later
revision changed or removed appearing in a rewritten file, or a check
built on kasane-pdf examining a different revision than a viewer shows
— but no actual information leak has been observed. Update if you
process incrementally updated files, in particular before rewriting
them.

## Verification

22 synthetic regression tests check which body each reference resolves
to (12 fail on 0.4.0), including rewrite and incremental save after a
hybrid-reference section; a new fuzz target (`xref_updates`) compares
every object of generated update chains with an independent model of
the rule.

## Upgrading

```toml
[dependencies]
kasane-pdf = "0.4"
```

`cargo update -p kasane-pdf`. No source change is required.
