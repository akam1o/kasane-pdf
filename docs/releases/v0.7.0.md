# kasane-pdf v0.7.0

## Overview

0.7.0 widens what `redact` can remove exactly — hairlines and strokes
under stroke adjustment, shadings and tiling patterns painting inside a
rect, documents that run scripts (on request) — and makes it faster on
large and font-heavy documents. Literal strings are now read as
ISO 32000 §7.3.4.2 says and written so that every reader reads them
back alike; where common readers disagree on what a document shows,
`redact` refuses instead of guessing.

MSRV stays 1.92. The release is breaking only in that `Redaction`
gains fields and becomes `#[non_exhaustive]` (see Compatibility).
Upgrading is recommended for every application that uses `redact`,
`remove_document_metadata` or the editors.

## Security

Three advisories, each fixed here; upgrading is recommended for every
application that uses `redact` or `remove_document_metadata`.

### Input object streams carried into the output ([GHSA-vph3-9p4m-58fh](https://github.com/akam1o/kasane-pdf/security/advisories/GHSA-vph3-9p4m-58fh), Medium)

- *What:* when an object of the input referred to one of its own object
  streams or cross-reference streams, the rewrite wrote that stream out
  verbatim. It still held the input's objects as they were: what
  `redact` removed (annotations and their text, links and their URIs) and
  the `/Info` that `remove_document_metadata` drops. No viewer shows the
  stream, but any PDF parser reads it.
- *Affected:* `redact` 0.6.0–0.6.2; `remove_document_metadata`
  0.1.0–0.6.2. Page text and images were not exposed this way.
- *Fixed:* a rewrite that edits or removes anything refuses such inputs,
  and `redact`'s verification fails on any carried object stream.

### Readers disagreeing on literal strings ([GHSA-f228-qvw7-4x37](https://github.com/akam1o/kasane-pdf/security/advisories/GHSA-f228-qvw7-4x37), Low)

- *What:* an unescaped carriage return in a literal string is a line feed
  for MuPDF (§7.3.4.2) and a CR for Poppler and pdf.js; glyph codes and
  positions after it differ. `redact` 0.6.0–0.6.2 could keep glyphs MuPDF
  draws inside the rect.
- *Fixed:* such strings are read as line feeds and `redact` refuses
  documents holding them.

### Readers disagreeing on CMap codes ([GHSA-xpph-r5fc-83rj](https://github.com/akam1o/kasane-pdf/security/advisories/GHSA-xpph-r5fc-83rj), Low)

- *What:* an embedded CMap writing codes as literal strings is applied by
  MuPDF and pdf.js and rejected by Poppler; `redact` 0.6.0–0.6.2 could keep
  glyphs those readers draw inside the rect.
- *Fixed:* `redact` refuses text in such fonts.

## Added

- `RedactOptions::remove_javascript` (CLI `--remove-javascript`,
  `Redaction::javascript_removed`): every JavaScript action and the
  `/Names /JavaScript` tree are removed instead of refusing a document
  whose catalog runs scripts; actions after a removed script in its
  chain stay. XFA forms, script sources referred to elsewhere and a
  catalog `/AA` are refused.
- Shadings (`sh`) painting only inside a rect are removed with
  everything they reach (`TargetKind::Shading`,
  `Redaction::shadings_removed`, CLI `shadings removed:`).
- `Warning::LiteralStringCarriageReturn`.
- `Limits` implements `PartialEq`, `Eq` and `Hash`.
- `scripts/bench-redact.py`, a fixed redaction timing benchmark.

## Behaviour changes

- Hairlines (`0 w`) and strokes, cut fills and stroked text under
  stroke adjustment (`/SA true`) are redacted as their user-space
  geometry instead of refused.
- Tiling patterns are decided where they paint: kept clear of the
  rects, removed with the pattern when wholly inside one; crossing,
  shared or also-painted-outside patterns and shadings are refused.
- An unescaped CR or CRLF in a literal string is read as one line feed
  (rendering and extraction follow). `redact` refuses a document holding
  such a string, and text in a font whose embedded CMap writes codes as
  literal strings: readers disagree on both.
- A rewrite that edits or removes anything refuses a document whose
  objects refer to an input object stream or cross-reference stream.
- Copies of removed text (`elsewhere`) are also looked for in optional
  content that is off and in annotation appearances; CR, LF and CRLF
  compare as one line end.

## Fixed

- Literal strings written by `redact` and the `remove_*` editors escape
  every control byte: a raw CR or LF was read differently by different
  readers, changing kept text in some (MuPDF showed other glyphs).
- Stroked text was grown by the stroke's reach under the wrong matrix
  in the diagnosis and the editors.

## Performance

A document loads each font once per operation and reuses it across
pages (kept per thread; `Document` stays `Send`); the copy search no
longer evaluates glyph outlines. On the redaction Corpus (234 runs) the
total time went from 45 s to 7 s with identical outputs; a 200-page
document in one font redacts in 0.21 s instead of 0.66 s, and a page
selecting one font 20,000 times no longer exceeds
`max_total_decoded_bytes`.

## Compatibility

- `Redaction` gains `fonts_embedded`, `shadings_removed` and
  `javascript_removed` and is now `#[non_exhaustive]`: a struct literal
  of it no longer compiles (it is a result; read its fields). Later
  fields will be additive. `cargo semver-checks` against 0.6.2 reports
  only that.
- `Warning::LiteralStringCarriageReturn` is the last variant: no
  discriminant moves.
- A document that previously rewrote with an object referring to its
  own object stream, through an edit, is now refused.

## Known limitations

`redact` stays positional and refuses what it cannot remove exactly
(the full list: `docs/features/redaction.md`, `docs/limitations.md`).
Notably refused: shadings and tiling patterns crossing a rect, curved
fills crossing a rect, XFA forms with `remove_javascript`, structure
trees with alternate text unless removed, non-embedded fonts other than
the Latin Standard 14 (with `embed_substitute_fonts`), and strings or
CMaps readers disagree on. Streams `redact` does not interpret
(attachments, private streams) are carried and not searched; copies of
removed content kept there stay. Geometry is exact in user space, not in
device pixels.

## Corpus (55 files, 117 runs)

- default 50 → 52, with `--embed-substitute-fonts --remove-annotations`
  77 → 79, adding `--remove-javascript` 80; one known evaluator false
  signal, unchanged.
- Characters lost outside the rects (Poppler): 2 of 73,501, unchanged.
