# kasane-pdf v0.4.0

## Overview

0.4.0 is a correctness release. Six silent misrenders that were
reported as exact renders are fixed (besides the `/FontMatrix` fix
already shipped in 0.3.1); `rewrite` carries optional content
instead of refusing it; text extraction recovers text that fonts
without `/ToUnicode` describe exactly — never by guessing — and, on
request, the text of annotations and form fields. Two defects present
in every earlier release are fixed: `extract_text` leaked about 36
bytes per call, and a simple font with `/FirstChar` or `/LastChar`
outside 0–255 made the library panic.

No public item was removed or changed in signature (`cargo
semver-checks` against 0.3.1: no semver update required); additions
are on `#[non_exhaustive]` types. The minor version is for what callers
observe — see *Behaviour changes*.

## Highlights

- **Rendering fixes** (each reported as an exact render before, each
  with a regression test that fails on 0.3.1):
  - Type 1 and CFF fonts with a non-standard `/FontMatrix` are drawn at
    their scale (shipped first in 0.3.1, part of this series);
  - the page group is isolated with a transparent backdrop (§11.4.7):
    non-Normal blend modes over unpainted page area no longer blend with
    white (a `/Difference` group came out in the complementary colour);
  - `/HardLight` on images, shadings and groups (§11.3.5);
  - stroked text (`Tr` 1, 2, 5, 6) uses the graphics state's line width
    in user space, with caps, joins and dashes (§9.3.6) — it was about
    7× too thin at 12 pt;
  - a text object inside a Type 3 glyph no longer moves the outer text;
  - annotations with NoRotate stay upright on rotated pages;
  - CFF fonts with the predefined ISOAdobe charset draw their glyphs
    instead of `.notdef`.
- **`rewrite` carries `/OCProperties`** (§8.11.4): validated, carried
  verbatim with renumbered references, written as at least PDF 1.5.
- **Text without `/ToUnicode`**: full Adobe Glyph List names (simple
  and Type 3 fonts), CFF built-in encodings, the embedded program's
  Unicode `cmap` read backwards (unambiguous glyphs only, bounded),
  Adobe-Japan1 CIDs with `cjk-fallback`. `ResolveKind::FontProgram`
  and `ResolveKind::CharacterCollection` say which source answered.
- **Annotation and form-field text**, opt-in:
  `TextOptions::with_annotations(true)` → `ExtractedText::annotations`
  (`AnnotationText`, `FieldText`): `/Contents`, `/RC`, field name /
  value / default value, and the appearance's characters, kept apart;
  `AnnotationText::text()` picks one without double counting.
- **Robustness**: no per-call leak in `extract_text`; no panic on
  out-of-range `/FirstChar` / `/LastChar`; Unicode `cmap`s are sized
  from their headers before being read; annotation collection is
  linear.

## Behaviour changes

| input | 0.3.1 | 0.4.0 |
|---|---|---|
| a code without `/ToUnicode` whose glyph name is in the Adobe Glyph List but not in the old table (`fi`, `minus`, `a.sc`, …), a Type 3 character name, a CFF built-in encoding name | `None` | the Unicode text (`EncodingFallback`) |
| a code of a font without `/ToUnicode` whose embedded program maps the glyph unambiguously | `None` | the text (`FontProgram`) |
| an Adobe-Japan1 Type 0 font without `/ToUnicode` (`cjk-fallback`) | `None` | the text (`CharacterCollection`) |
| a code that already resolved | — | unchanged |
| a page naming a non-Normal blend mode | blended over white | over a transparent page group, then on white (±1–2 levels where nothing blends) |
| stroked text | wrong width | user-space width |
| catalog `/OCProperties` in `rewrite` | `Unsupported` | carried (malformed: `Structure`) |
| CFF Expert / ExpertSubset charset | `.notdef` drawn | `Unsupported` |
| an overlapping tiling pattern needing more than `max_pattern_tiles` cells (now counted exactly) | drawn (in the one corpus case: wrongly) | `LimitExceeded` |
| simple font with `/FirstChar` / `/LastChar` outside 0–255 | panic | loads; widths outside 0–255 ignored |

Upgrading needs no code change. `ResolveKind` is `#[non_exhaustive]`:
a `match` on it already has a wildcard arm, which the two new kinds
reach. The new variants come after the existing ones, so their numeric
values are unchanged.

## Known limitations

- **NoZoom** has no effect (`RenderOptions` has no viewer zoom).
- **CFF Expert / ExpertSubset charsets** are refused (`Unsupported`).
- **DeviceCMYK** uses the §10.3.5 conversion, without colour management
  (ΔE00 ≈ 5–25 against Poppler / Acrobat on saturated colours).
- The compat runner's **ΔE00 colour comparison is report-only** and is
  not part of the library.
- **`max_pattern_tiles`**: overlapping tiling patterns are executed
  cell by cell; one corpus document is now refused (raise the limit to
  render it).
- **Text without `/ToUnicode`**, unresolved on purpose: names without
  glyph-list meaning (`g12`), symbol-only `cmap`s, ambiguous glyphs,
  Identity-ordering CID-keyed CFF, GB1 / CNS1 / Korea1 (no bundled UCS2
  mapping), `cmap`s above 131 072 code points.
- **Annotation text**: `/RC` is not interpreted; field values are per
  page; appearance text needs a drawable appearance.
- **Thin strokes** are drawn at true coverage (Poppler widens them to a
  device pixel).
- **Encrypted documents** are read only; writers refuse them.

## Verification

- Compatibility corpus, 511 files, Linux nightly (Poppler 26.01 with
  `poppler-data`), `expect: pass` (425): strict parse 408, render 380,
  text 392, rewrite 364 (0.3.1: 350), all four 338 (0.3.1: 325);
  44 / 44 adversarial files refused without crash or timeout; 427
  rewrites, 424 identical on every comparison, 203 semantic passes.
  Text agreement, page 1 vs pdftotext, on the 250 `expect: pass`
  documents with text: F1 ≥ 0.9 on 213 (207 before the text work),
  CJK 17 / 17 — identical on Linux and macOS. Across the first 30
  pages of every file: 15 088 characters recovered, 50 not in
  pdftotext's output (line-end hyphens it drops, a "±" it omits), none
  altered.
- Fuzzing on the release candidate (cargo-fuzz, libFuzzer): `open_any`,
  `encrypt_dict`, `ciphertext` and the new `text_sources` (font programs
  without `/ToUnicode`, annotation dictionaries) — `text_sources` 30 +
  10 min, `open_any` 15 + 15 min, the encryption targets 7.5 min each,
  about 3.9 million runs; no timeout, OOM or slow unit. The one crash
  found (the `/LastChar` panic) is fixed and kept as a seed.
- Independent reviews of every series; their P0 / P1 findings fixed
  with regression tests.
