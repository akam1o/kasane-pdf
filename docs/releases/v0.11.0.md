# kasane-pdf v0.11.0

## Overview

0.11.0 reads more damaged files in recovery mode, reports what each
annotation shows, bounds the work of dashed strokes across a render, and
fixes a security issue in redaction.

- **Recovery mode**: five more rules, each recorded as a
  `Warning::RecoveryApplied` — operators with the wrong number of
  operands, form XObjects without `/BBox`, functions given extra inputs,
  shading functions with extra outputs, and JBIG2 / JPEG codestreams of
  another size than their image dictionary
  ([`recovery-mode.md`](../recovery-mode.md), which states what region
  redaction does with each).
- **Annotation text**: `AnnotationText::shown_text()` and `note()`, and
  `text --annotations` in the CLI
  ([`annotation-text.md`](../annotation-text.md)).
- **Dashed strokes**: one outline budget per render; a page that repeats
  dashed strokes ends in an `Unsupported` error instead of rendering for
  minutes.
- **WinAnsiEncoding**: its unused codes draw and extract as the bullet
  (ISO 32000-1 Annex D).

MSRV stays 1.92. The API change is additive (new `RecoveryRule`
variants, `AnnotationText` methods and field; both types are
`#[non_exhaustive]`). Some error messages give an offset, an index or
the kind of the problem instead of the values they stopped at — branch
on `Error::kind()`, not on message text.

## Security

One advisory, fixed here; upgrading is recommended for every
application that uses `redact` or the content removers and logs or
shows their errors.

### Refusals that quoted the document ([GHSA-4q38-qhh6-c256](https://github.com/akam1o/kasane-pdf/security/advisories/GHSA-4q38-qhh6-c256), Low)
- *What:* when `redact` or a content remover refused a page, the error's
  message could include values taken from the document: the character
  code of the first glyph whose outline could not be evaluated (for a
  simple font with a standard encoding, the character itself), bytes of
  a damaged token or stream, a ToUnicode entry, a signature field's name,
  an XFA packet's name, a button field's state, a CIDFont ordering or
  `/W` CIDs. `redact --explain` listed every such glyph's code. Nothing
  was written; the refusal itself was right.
- *Affected:* `redact`, `remove_region(s)`,
  `remove_regions_and_document_metadata`, `remove_text`,
  `remove_image_region` and the CLI, 0.1.0–0.10.0, where the message
  reaches someone who does not have the document (a log, a user
  interface, error reporting).
- *Fixed:* refusals give the cause and the position (a byte offset, an
  object number, an index) only.
  [`security.md`](../security.md) lists which interfaces carry the
  document's content and must be handled like it.
- *Workaround:* branch on `Error::kind()` and do not forward the
  message.
