# kasane-pdf v0.10.0

## Overview

0.10.0 redacts many documents earlier versions refused, and makes
`redact` check its own output independently of what the edit recorded.
0.9.0 was prepared but never released; everything it contained is part
of this release.

- **More is cut instead of refused**: filled shapes of any form (curves,
  polygons, self-intersecting paths), axial shadings and rectangles
  filled with a tiling pattern that cross a rect — each only when what
  stays outside shows everything the rect showed.
- **Forms**: widgets and their form fields (with `remove_annotations`),
  and the XFA part of a hybrid form (with `remove_javascript`, or when
  fields are edited).
- **Fonts and images**: substitutes for non-embedded TrueType fonts
  named after the Standard 14 fonts; images at 1, 2 and 4 bits, through
  filter chains, in CCITT and JBIG2.
- **Independent verification** of the output, and a written model of
  what a success guarantees:
  [`docs/redaction-safety-model.md`](../redaction-safety-model.md).

MSRV stays 1.92. The API change is additive (`Redaction::fields_removed`,
`shadings_cut`, `xfa_removed`); `redact` refuses some outputs 0.8.0
returned and accepts many inputs it refused (see Compatibility).
Upgrading is recommended for every application that uses `redact`.

## Newly redacted

- **Filled shapes crossing a rect**: any fill — curves, polygons,
  self-intersecting or several subpaths, overlapping or rotated
  rectangles — keeps its part outside the rects with its own fill rule;
  nothing of its geometry inside stays.
- **Axial shadings** (type 2, page content, axis-aligned, under a
  rectangular clip or none): cut when every colour the rects show is
  also shown outside them on the page, and painted once more outside the
  rects (`Redaction::shadings_cut`). Radial, function-based and mesh
  shadings, and shadings in forms, stay refused.
- **Tiling patterns**: a rectangle filled with one is cut when its part
  outside the rects shows a whole period. Text, strokes and other shapes
  painted with a pattern stay refused.
- A cut shading or pattern keeps its data whole in the output (function,
  cell): the cut is accepted only when none of it was shown by the rects
  alone.
- **Widgets and form fields** (`remove_annotations`): a widget meeting a
  rect goes, and its field with it when no widget of the field is left —
  value and description too (`Redaction::fields_removed`). A field keeping
  widgets keeps its value only if a kept widget is shown and, for a
  button, shows that value's state. Signature fields and field trees that
  cannot be edited exactly are refused.
- **XFA**: with `remove_javascript`, or when fields are edited, an XFA
  form beside its AcroForm is removed (`Redaction::xfa_removed`) — its
  packets hold the scripts and a copy of the field values. Verification
  checks that no packet, link to one or copy of its bytes stays. A form
  that renders from XFA alone is refused.
- **Scripts**: with `remove_javascript`, what is left of the catalog's
  `/AA` after its scripts go is kept.
- **Popups** without an appearance stream are no longer refused for
  NoZoom or NoRotate: they draw nothing on the page.
- **Fonts**: `embed_substitute_fonts` also replaces non-embedded,
  non-symbolic simple TrueType fonts named after a Standard 14 font or
  an alias (ArialMT, TimesNewRomanPSMT …).
- **Images** at 1, 2 and 4 bits per component (samples set to 0 at their
  own depth), through chains of general filters, and in CCITTFax or JBIG2
  without `/JBIG2Globals`; the edited copy is written unfiltered.

## Fixed

- `embed_substitute_fonts` (0.7.0–0.8.0) wrote a code whose glyph the
  substitute cannot name as `.notdef`; some readers draw such a code as
  its own glyph, where `redact` had not placed it. It is now the
  substitute's blank space glyph.
- An embedded Type 1 font whose encoding names a glyph the program lacks
  (or `.notdef`): `redact` (0.6.0–0.8.0) placed the code as `.notdef`,
  while MuPDF draws the program's own glyph for it. Its extent is now
  every glyph the program can draw.

## Independent verification

Before returning, `redact` compares the input with the re-parsed output,
without consulting the edit's own record:

- **Use**: every stream an edited page read to picture or spell content —
  contents, forms, appearances, images and masks, Type 3 procedures of
  glyphs shown, patterns, soft mask groups, shadings, functions, colour
  tables — is drawn again by the output or absent from it, by digest,
  whatever object number or reference keeps a copy. The walk reads the
  graphics state as readers do: each parameter's latest value, with the
  resources it was selected in; optional content by the default viewing
  configuration; a button's states as it presents them. A name that
  resolves to nothing counts, over the input, as using everything the
  page reaches.
- **Non-interference**: every page not edited draws from the same
  streams as before, under a bound that counts everything a reader may
  draw (every appearance state, hidden annotations, optional content).
- **Removed annotations and fields**: none is written — checked by
  identity on the edited document and against the rewrite's object map —
  and no dictionary of the output holds one's content. What they held
  (actions and their targets, text, popups, the objects of their
  appearances) stays only where something that uses it keeps it — a
  kept page, annotation or field, an outline item, a destination, the
  catalog, a name tree, each read by the entries it defines; an action
  only where it is used as one, the annotation's own data only as the
  value of an entry defined to hold data (limits: `docs/limitations.md`).
- **XFA**: no removed packet is in any stream of the output, by stored
  or decoded digest.
- **Reachability**: every output object is reachable from the trailer.

The earlier digest checks stay alongside, as a second layer. Passing
them is not a proof that no copy of the removed content remains: what
is and is not covered is in the safety model, and the limits in
[`docs/limitations.md`](../limitations.md).

## Tests

- `tests/redact_model.rs` and the `redact_model` fuzz target generate
  documents in two variants that differ only in what lies inside the
  rect — including hidden and optional content, thumbnails, the inside
  of filled shapes, shading bands and tiling fills — and require
  byte-identical outputs or the same refusal (10,000 generated cases in
  release testing; a false success fails like a crash). This is
  evidence for the verification over the constructions the generator
  produces, not a proof over all documents.
- `tests/redact_advisories.rs`: one regression test per published
  advisory; `scripts/check-advisory-regressions.py` judges any CLI with
  qpdf and pdftotext. Results per version:
  [`docs/security/advisory-regressions.md`](../security/advisory-regressions.md).
- The new cuts were checked with Poppler, MuPDF and pdf.js at 72, 150
  and 300 dpi on synthetic inputs: no ink inside the rects; the
  differences outside lie on anti-aliased edges (curve flattening,
  pattern pixel snapping), not lost content.

## Performance

Against 0.8.0 on the synthetic benchmark (`scripts/bench-redact.py`,
median of 3): −4 % to +10 % (many fonts most; resource-heavy pages and
large text slightly faster). 32,000 annotations: 4.0 s → 1.1 s;
preflight of 300,000 structure attributes: 1.24 GB → 0.37 GB peak
memory. The new paths scale linearly on synthetic inputs (largest
measured: 5,000 widgets 0.31 s / 36 MB; 1,000 curved fills crossing a
rect 0.04 s / 20 MB; 1,000 pages 0.03 s; 1,000 tiling fills 0.01 s; an
embedded Type 1 program of 2,000 glyphs on 300 edited pages 0.49 s →
0.70 s). Inputs past a limit (field trees deeper than 64, forms nested
more than 16 deep, reference chains past `max_reference_depth`, cuts
past their budget) are refused at once.

## Corpus

On the 117 redaction runs of the corpus (`compat/redaction/`; page 1 of
each file, a word, its line and a central block):

| options | 0.8.0 | 0.10.0 |
| --- | ---: | ---: |
| default | 60 | 65 |
| `embed_substitute_fonts` + `remove_annotations` | 90 | 99 |
| … + `remove_javascript` | 91 | 104 |
| … + `refuse_uninspected` | 87 | 100 |

Text and drawing kept outside the rects are unchanged. The 117 runs are
one evaluation set chosen to exercise hard cases; 104 of 117 (88.9 %)
says nothing about the share of other documents `redact` accepts, which
depends on what they contain. A refusal is the intended outcome for
anything `redact` cannot verify.

## Compatibility

- Additive: `Redaction::{fields_removed, shadings_cut, xfa_removed}`
  (the struct is `#[non_exhaustive]`); the CLI prints them.
  `cargo semver-checks` against 0.8.0: no semver update required.
- Refused now: outputs that keep a content-bearing stream an edited page
  used without using it; removed annotations or fields, or data they held,
  that only private data still refers to (also some unusual sharing: a
  removed link's action stored where another element defines no action;
  forms and images with an optional content membership dictionary on
  an edited page); some documents whose optional content or
  appearances readers present differently (`docs/limitations.md`).
- Accepted now: filled shapes, axial shadings and tiling fills crossing a
  rect (as above), widgets, hybrid XFA forms, the catalog `/AA` after
  script removal, bare popups, TrueType substitutes, low-bit images,
  filter chains, CCITT, JBIG2 without globals.
- The output of a page with a cut shape, shading or pattern differs
  from 0.8.0's (which refused it); a text in an embedded Type 1 font with
  missing glyph names may lose a code near a rect that 0.8.0 kept.
