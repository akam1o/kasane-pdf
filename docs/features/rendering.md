# Rendering & text — support matrix

Page→pixmap rendering (`render_page`), text rendering/extraction,
and the related limits. Anything outside the listed subset is a
typed `Error::Unsupported` — never a partial render.


## Rendering (ISO 32000-1 §8, §9)

`render_page` executes supported operations into a `Pixmap`
(`tiny_skia`) over a white background; `pixmap_to_png` encodes it.
Only pages whose operations all fall inside this subset render —
anything else fails with `Error::Unsupported` and produces no output.

| Feature | Status | Notes |
|---|---|---|
| `q`/`Q`/`cm` | ✅ | *special graphics state* ops (§8.2 Table 51), allowed at page description level only — inside a path object they are `Error::Structure` (§8.2 Figure 9). Paths are built in user space; `CTM × page→pixmap` is applied at paint time. `cm` composes as `CTM' = M × CTM` (`m.concat(ctm)` — the operand maps the *new* user space into the old one), the same rule a form `/Matrix` and a Type3 `/FontMatrix` follow; pinned by `tests/render_basic.rs::nested_cm_order` after the Poppler oracle caught the reversed order misplacing everything under a nested transform |
| `m` `l` `c` `v` `y` `h` `re` | ✅ | accumulate in the current (user-space) path; `m`/`re` begin a path object |
| `S` `s` `f` `F` `f*` `B` `B*` `b` `b*` `n` | ✅ | nonzero-winding and even-odd rules; open subpaths are implicitly closed for filling |
| `W` `W*` | ✅ | mark the current path as the clip operand (must follow the *last* construction op — §8.5.4); the clip installs when the path is *consumed*: a paint op draws under the **pre-W** clip first, then the clip updates; `W`+`n` installs without painting; `W` on an empty path empties the clip; `q`/`Q` save/restore |

**Placement enforcement** (§8.2 Figure 9, §8.5.4): inside a path
object only path-construction ops, `W`/`W*`, and the terminating
painting/`n` op are allowed. The renderer rejects out-of-order
operators with `Error::Structure` — e.g. `cm`, `q`/`Q`, colour ops,
`m`/`l`/`re` after `W`/`W*`, a second `W`/`W*` in the same path, or
`l`/`c`/`v`/`y` without a current point. The parse-only
`page_operations()` API still returns these sequences; placement is
a *render-time* restriction, not a parsing one.
| `w` `J` `j` `M` `d` `i` | ✅ | line width 0 → 1-device-pixel hairline (§8.4.3.2) |
| `G` `g` `RG` `rg` `K` `k` | ✅ | DeviceGray/RGB/CMYK — remapped through a `/DefaultGray`/`/DefaultRGB`/`/DefaultCMYK` entry of the current `/Resources /ColorSpace` when present (§8.6.5.6) |
| `CS` `cs` + `SC` `sc` `SCN` `scn` | ✅ | every colour-space family of §8.6 (`src/colorspace.rs`): Device*, `CalGray`, `CalRGB`, `Lab` (XYZ → Bradford to D65 → sRGB), `ICCBased` (see below), `Indexed` (string or stream lookup, index rounded and clipped to `hival`, short tables zero-padded), `Separation`/`DeviceN` (tint transform through `src/function.rs`: sampled type 0 with multilinear interpolation, exponential 2, stitching 3, PostScript calculator 4 — operand stack ≤ 100, 100 k steps, tables ≤ 2²² values; `/None` colorant paints nothing). `cs` resets the colour to the space's initial value (all-1 tints, CMYK `0 0 0 1`). Wrong component count → `Error::Parse`; malformed definitions (missing parameter dict, bad `/WhitePoint`, `hival` > 255, nested `Indexed`, tint-transform arity mismatch, self-referencing resource names) → `Error::Structure`/`LimitExceeded` |
| `ICCBased` | ◐ | `src/icc.rs` evaluates **matrix/TRC RGB** (`rXYZ`/`gXYZ`/`bXYZ` + `curv`/`para` curves) and **gray** (`kTRC`) profiles exactly, D50 PCS → Bradford → sRGB. LUT-based (`A2B0`), CMYK and Lab-PCS profiles, unreadable or undecodable streams fall back to `/Alternate` (or the device space by `/N`) as §8.6.5.5 permits **and the page records it** in `RenderedPage::color_approximations` — the compat runner lists those files separately; they are never counted as a faithful render. `/N` ∉ {1,3,4}, or an `/Alternate` whose component count disagrees → `Error::Structure`. No external CMS: deterministic, no new dependency, WASM-safe |
| `SCN` `scn` pattern name, `/Pattern` space | ◐ | `/Pattern` is a colour space like any other (`[/Pattern base]` keeps the base for uncoloured tiling patterns); `scn /P` selects a **`/PatternType 2` shading pattern** — fills paint the shading through the path as a clip, in pattern space = the page's or enclosing form/Type 3 glyph's base CTM × `/Matrix` (§8.7.3.1), with `/Background` where the geometry does not reach. Fills with no pattern selected paint nothing (the initial pattern colour). `/PatternType 1` tiling patterns, pattern **strokes**, pattern-filled **text** and a shading pattern carrying `/ExtGState` → `Error::Unsupported`; a pattern name outside the `/Pattern` space or missing from `/Resources /Pattern` → `Error::Parse`/`Structure` |
| text ops `Tf` `Tj` `TJ` `'` `"` | ✅ | embedded `/TrueType` + `/FontFile2` with any simple-font encoding (see *simple-font encodings* below) *or* `/Type0` with `Identity-H`, `Identity-V` or an **embedded CMap stream** (`src/cmap.rs`: 1–4-byte codespaces, `cidchar`/`cidrange`, `usecmap` Identity only, `/WMode`) over a `CIDFontType2` (`/FontFile2` or `/FontFile3 /OpenType`) *or* `CIDFontType0` (`/FontFile3` bare CFF — CID → GID through the CID-keyed charset, CID = GID otherwise; sfnt-wrapped programs are detected by signature whatever the declared subtype); vertical writing uses `/DW2`/`/W2` and positions glyphs by their vertical origin (§9.7.4.3); predefined non-Identity CMaps (`90ms-RKSJ-H`, `UniJIS-*`) stay `Unsupported` — the Adobe CMap resources are not bundled *or* `/Type1`/`/MMType1` + `/FontFile3` (raw CFF) *or* `/Type1`/`/MMType1` + `/FontFile` (Adobe Type 1 / eexec); `BT`/`ET` init `Tm`/`Tlm`; `Tc`/`Tw`/`Tz`/`TL`/`Tr`/`Ts` honoured — `Tw` applies to single-byte code 32 only (never to 2-byte Identity-H codes, §9.3.3); modes 0–3 painted (4–7 → `Unsupported`); PDF widths (`/Widths`, `/DW`/`/W`; the array itself may be indirect) used for advance — font-internal `hmtx` never consulted for *advance*. TrueType outlines are placed the way FreeType/Acrobat place them: when the `hmtx` left side bearing differs from the `glyf` header xMin the outline is shifted by `lsb − xMin` (composites take the `USE_MY_METRICS` component's values) — `hmtx` is consulted for that origin shift only. `/Type3` supported: each glyph's `/CharProcs` stream runs like a mini Form XObject under `/FontMatrix × Trm × CTM` (glyph → text → device; nested `BT…ET` bounded by `max_xobject_depth`). **eexec `/FontFile`:** `src/type1.rs` parses the PFB/PFA container, eexec-decrypts the Private dict (`/lenIV` honoured), decodes `/Subrs` + `/CharStrings`, and interprets Type-1 charstrings — full path ops (moveto/lineto/curveto incl. `vh`/`hv` alternating), hsbw/sbw widths, hint recording (hstem/vstem(+hm)/3-stem), `hintmask`/`cntrmask` mask bytes, `callsubr`/`return` (bounded depth), `callothersubr` (`arg1…argN N othersubr#` — othersubr# on top) with flex (OtherSubrs 0/1/2 through the standard Subrs 0–3), hint replacement (OtherSubrs 3 hands the Subr index back to `pop`), counter control (12/13) and the arithmetic OtherSubrs; unknown OtherSubrs re-expose their arguments to `pop` (FreeType rule); `div`, `setcurrentpoint`, `seac` composites via StandardEncoding. Operands use the Type 1 number forms — the 5-byte form is a 32-bit *integer*, not Type 2's 16.16. The RD/ND procedures are matched by position, so t1utils/cm-super programs that spell them `-|`/`|-` parse too. A program with no `/CharStrings` is a `Structure` error, never a font that silently draws nothing. Type-2-only opcodes (24–27) and unimplemented escapes → strict `Unsupported`. Bounded by `MAX_OPS`/`MAX_STACK`/`MAX_CALL_DEPTH`/`MAX_PATH_ELEMS` — malformed programs error, never panic/hang. Refused: `/FontFile3` CIDFontType0C, non-device encodings |
| simple-font encodings (§9.6.6) | ✅ | `src/encodings.rs` holds `StandardEncoding` and `MacRomanEncoding`; `WinAnsiEncoding` in `font.rs`. **Type 1 / CFF:** base = the named encoding, else the dict's `/BaseEncoding`, else the **embedded program's own `/Encoding`** (cleartext `dup <code> /<name> put` table, or `StandardEncoding`) — Table 114; `/Differences` overlays any base. **TrueType non-symbolic:** base = named / `/BaseEncoding` / `StandardEncoding`; name → Unicode → `(3,1)` cmap, then Mac OS Roman code → `(1,0)`, then `post` name, then `gNN`/`glyphNN` index. **TrueType symbolic** (`/Flags` bit 3 set, bit 6 clear): no implicit base — `/Differences` names first, then the code itself through `(3,0)` at `code`, `0xF0xx`, `0xF1xx`, `0xF2xx`, then `(1,0)` at `code`; a font with no `cmap` uses the code as the glyph index; a symbolic font that only has a `(3,1)` cmap maps StandardEncoding names into it. `uniXXXX`/`uXXXX[XX]` names resolve to Unicode. No glyph is ever chosen by position in a table the font did not define — a code with no mapping is `.notdef`. `MacExpertEncoding` and unknown encoding names → `Error::Unsupported`. Text extraction follows the same tables (`/ToUnicode` first, then glyph name → AGL) |
| text-state ops `Tc` `Tw` `Tz` `TL` `Tr` `Ts` `Td` `TD` `Tm` `T*` | ✅ | state persists across text objects; `Tm`/`Tlm` reinitialized by `BT` |
| `extract_text` (§9.10) | ✅ | one `CharInfo` per character code (1- or 2-byte per font), content order incl. Form XObjects; `/ToUnicode` CMap (1- or 2-byte codespace, `bfchar`, `bfrange` sequential + array, UTF-16BE/surrogates/multi-scalar) → WinAnsi glyph-name→AGL→Unicode fallback for simple fonts / `Unresolved` for Identity-H composites (no guessing); `/Span` `/ActualText` and `/OC` membership → `Error::Unsupported`; `/Annots` do **not** block extraction — annotation appearance streams are a separate layer whose text is never part of the page content (the same cut `pdftotext` makes), while *render* still refuses annotated pages; `bfrange` increments only the low byte of the last UTF-16 unit (destinations above U+00FF such as `<2212>` work; a range ending exactly at 0xFF is legal); headless — no rasterizing, clip masks, or image decoding; non-embedded Type1 fonts extract (metrics-only: `/Widths`+encoding, `bounds`→`None`) even though render refuses; user-space coords (`/Rotate` not applied); budgets: `max_text_codes`, `max_extracted_unicode_bytes` |
| `Do` | ✅ | Form XObject (§8.10): gs saved, `/Matrix` concatenated as `Matrix × CTM` (`tests/render_basic.rs::form_matrix_under_cm_order`), clipped to `/BBox`, form content runs under its own `/Resources`, gs restored; nested forms and recursion detection bounded by `max_xobject_depth`/`max_xobject_invocations`. Image XObject (§8.9): `/BitsPerComponent` 1/2/4/8/16, any colour space of §8.6 (per-image LUT for 1-component spaces, bounded cache for the rest), `/Decode` with the per-space defaults of Table 90, raw/`FlateDecode` (+predictors)/`DCTDecode` (gray/YCbCr/CMYK/YCCK; Adobe-inverted CMYK undone so `/Decode` applies to the stored samples), `/ImageMask` stencils painted in the fill colour (`/Decode [1 0]` honoured), `/SMask` soft masks folded into the image alpha as **straight alpha** (nearest-resampled when the mask size differs, `/Decode` applied; `/SMask` wins over `/Mask`), stencil `/Mask` streams and colour-key `/Mask` arrays. The decoded image is one straight-RGBA buffer composited per device pixel with the §11.3.8 formula (`αr = αb + αs − αb·αs`, blend-mode term `B(cb, cs)` for the separable modes), clip coverage × image alpha × `ca` as the source alpha, so a soft-masked image under `ca`, a blend mode, a rotated/mirrored CTM, a clip, or inside a nested form all go through the one path; minified images average up to 4×4 sub-samples per pixel, magnified ones sample nearest. Refused: `/Matte` (pre-blended soft masks), `/SMaskInData` ≠ 0 (JPX alpha), `/OC`, `/Ref`, non-separable blend modes on an image, a `/Pattern` colour space on an image (structure error). **Inline images** (`BI … ID … EI`, §8.9.7) go through the same pipeline with the Table 93/94 abbreviations expanded; the parser computes the data end (unfiltered length from `/W`/`/H`/`/BPC`/colour space, JPEG `EOI`, a *complete* zlib stream before a delimited `EI`, `AHx`/`A85` EOD; other filters: the first delimited `EI` followed by content-stream text) so an `EI` byte pair inside the data never truncates it. Invalid dimensions, short data, bad `/Decode`, a mask that is not a 1-component image, a self-referencing `/SMask` → typed errors, bounded by `max_image_dimension`/`max_image_total_samples`/`max_image_bytes` (decoded RGBA counted). Transparency groups (`/Group /S /Transparency`, §11.6.6): opaque-Normal → inline; under `ca` < 1 or a separable blend mode → painted into a page-sized offscreen layer (alpha/blend reset inside, counted against `max_render_buffer_bytes`) and composited once with the group's `ca` and `BM`; non-Normal blend modes *inside* an isolated-inline or non-isolated-layer group, knockout groups (`/K true`) and non-separable group blend modes → `Error::Unsupported` (those are the cases where the backdrop would change the result) |
| `sh` | ◐ | `src/shading.rs`: **type 2 (axial)** and **type 3 (radial)** — `/Coords`, `/Domain`, `/Function` (any §7.10 type, sampled into a 256-entry sRGB table through the shading `/ColorSpace`, ICC approximations recorded), `/Extend` (radial: largest `s` with `r(s) ≥ 0`, extended circles painted per §8.7.4.5.4), `/BBox` (clip), `/Background` ignored for `sh` (pattern use only); painted per device pixel over the current clip with `ca` and the separable blend modes through the §11.3.8 compositor. Types 1 (function-based) and 4–7 (meshes/patches) → `Error::Unsupported`; a missing `/Shading` resource, a degenerate `/Domain`/`/Extend`/`/Coords`, a function whose arity disagrees with the colour space, or an `Indexed`/`Pattern` colour space → `Error::Structure`. A degenerate axis (coincident points) paints nothing |
| `gs` | ✅ | `/ExtGState` applied (§8.4.5): `LW`/`LC`/`LJ`/`ML`/`D` map onto the same line fields as `w`/`J`/`j`/`M`/`d`; `ca`/`CA` multiply the paint-time alpha; `BM` maps all 16 standard blend modes to tiny-skia (`/Normal`,`/Compatible`→SourceOver); `RI`, overprint `OP`/`op`/`OPM`, `SA`, `AIS`, `TK`, `SMask` `/None`, `TR`/`TR2`/`BG`/`UCR` `/Default`, `HT`/`FL`/`SM` accepted. Real `/SMask` (luminosity/alpha), non-`/Default` transfer functions, `/Font` via gs, and unknown keys → `Error::Unsupported` |

Non-string `/ActualText` → `Error::Structure` |
| `/OC` `/OCMD` marked content, XObject `/OC`, annotation `/OC` | ✅ | `src/optcontent.rs` evaluates the document's **default configuration** (§8.11.4): `/OCProperties /OCGs`, `/D` `/BaseState` `/ON` `/OFF`, and `/D /AS` usage-application dictionaries for the `/View` event (`/Usage /View /ViewState`); OCMDs by `/VE` (`/And` `/Or` `/Not`, depth ≤ 32, ≤ 1024 nodes) or `/OCGs` + `/P` (`/AnyOn` default, `/AllOn`, `/AnyOff`, `/AllOff`). ### Colour conversion notes

- `DeviceCMYK` → RGB uses the naive subtractive form
  `1 − min(1, c + k)` (§10.4.3 note). Device spaces are **not**
  colour-managed; `ICCBased` matrix/TRC and gray profiles and the
  CIE-based spaces are converted through XYZ with a Bradford
  adaptation to D65 and the sRGB transfer curve (`src/icc.rs`).
  Anything the engine cannot convert exactly uses the `/Alternate`
  and is reported in `RenderedPage::color_approximations`.
- Colour values are clamped to [0,1] for output encoding; out-of-range
  input saturates rather than erroring (the spec clamps at the device).
