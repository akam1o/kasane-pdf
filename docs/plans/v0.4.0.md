# Plan — v0.4.0: correctness first

Status: analysis and plan (2026-10-31), on v0.3.0 (`fff1f49`), corpus run
run-1793406122. Per-file evidence lives in the gitignored
`compat/reports/v040/`; this file carries only aggregates, anonymised
causes and the plan.

## Method

| phase | how |
|---|---|
| strict blockers | every `expect: pass` file without a strict render (48) re-run page by page, strict and recovery, every distinct error recorded (not only the first); Poppler (`pdftoppm`) and `qpdf --check` as witnesses for the 29 that also fail in recovery |
| approximations / fidelity | the runner's per-file metrics (SSIM, content SSIM over inked windows, diff at best ±3 px shift, ink coverage, size mismatch) re-analysed for all 379 strict renders; a CIE ΔE colour comparison against Poppler at 48 dpi (362 files with a reference); the 23 worst-scoring *exact* renders and the 8 worst colour outliers inspected side by side |
| writers | the runner's round-trip results (rewrite → reparse → structure / render / text / annotations / qpdf); plus a new probe: an `/Info` edit saved with `Edit::save_incremental` on all 449 strictly parsed files, checked for byte-prefix preservation, reparse, visibility of the edit, page count, qpdf and Poppler |
| CJK | a font inventory of all 511 files (every font reachable from the first 200 pages: subtype, descendant, ordering, CMap, program, `ToUnicode`); text compared with `pdftotext` both order-sensitively (LCS) and as a character multiset (bag F1) |
| corpus | the committed manifest (source, producer, version, licence, size, pages, category, features) |

## 1. Strict render blockers (48)

| class | meaning | files | of which render in recovery |
|---|---|---:|---:|
| A | spec-conforming feature missing | 2 | 0 |
| B | spec-permitted fallback missing | 1 | 0 |
| C | invalid input — recovery only | 25 | 18 |
| D | needs an approximation (and is invalid) | 1 | 0 |
| E | resource limit, refused correctly | 2 | 0 |
| F | encryption (password needed, damaged encrypted table, Acrobat short key) | 3 | 1 |
| G | other invalid / undefined input, correctly refused | 14 | 0 |

- **A (2):** `/BrotliDecode` (PDF 2.0 extension filter); a form-field
  value outside Latin-1 with a single-byte field font (needs a Unicode
  field font for appearance synthesis).
- **B (1):** a non-embedded *TrueType* font whose name has no sound
  substitute. Substitution of non-embedded fonts is what the standard
  expects of a reader; the missing part is a metric-compatible generic
  fallback, reported as an approximation.
- **C (25):** 18 already render in recovery (operator inside a path
  object ×3, missing `/MediaBox`, damaged xref ×7, stray `Q`, invalid
  annotations, …). **7 recovery gaps**: a second fault after the
  first recovery rule — an operator with too few operands (×3, Poppler
  draws by ignoring it), a page-tree cycle, an unbalanced `)` in an
  object, a form without `/BBox`, a type 3 function with the wrong
  input count. The operand-count case is the only one with a reading
  shared by the major readers.
- **D (1):** shading function output count ≠ colour-space components.
- **E (2):** form nesting deeper than `max_xobject_depth`; an image
  over `max_image_dimension` behind a missing `/MediaBox`. Limits stay.
- **G (14):** non-embedded Identity-ordering CID fonts (×3 — no sound
  glyph mapping), multi-state appearances without `/AS` (×2), JBIG2 on
  a content stream, a JBIG2 or JPEG frame size that contradicts the
  image dictionary (×2), corrupt Flate, inline image without `EI`, a
  pattern cell that paints itself, unrecoverable structure (×3), a
  `/Template` in the page tree. Poppler also fails or warns on 8 of
  the 14.

Ceiling without loosening strict mode: A + B + D = 4 files (379 → 383,
89.7 %). 385 needs the corpus to change, not the engine; the plan does
not chase it.

## 2. Approximate renders (69 of 379) and fidelity

| cause | files | spec-correct drawing | removable? |
|---|---:|---|---|
| non-embedded Standard-14 / Latin font → Liberation | 67 (1 also Symbol) | the font's own glyphs (unknown to the file) | no — the file does not carry them; metric-compatible substitution is the best available and is reported |
| Symbol / ZapfDingbats fallback | 1 | as above | no |
| oversized JPEG decoded at reduced DCT scale | 1 | full-resolution decode | only by raising the limit |
| ICC profile with Lab PCS → `/Alternate` | 1 | evaluate the profile | yes: Lab-PCS ICC (≈2 d) |

The approximate renders are *not* the fidelity problem: their median
diff-at-shift (1.0 %) is within the exact renders' (0.8 %), ink coverage
matches (median ratio 1.00). The problems are in renders reported as
**exact**:

| finding | files (corpus) | severity |
|---|---:|---|
| **Type 1 font `/FontMatrix` other than 0.001 ignored.** eexec programs: the matrix is read from the decrypted Private section, but it lives in the cleartext part; CFF (`/FontFile3 /Type1C`) simple fonts: always 1000 units/em. Glyphs of a 2048-unit font are drawn 2× too wide and overlap — text visibly garbled, reported as an exact success | 9 contain such a font; **3 visibly garbled**, all reported exact (re-measured after the fix: 5 more only carry an oblique font not drawn on the compared pages, 1 is refused by a limit) | **P0 — fixed** (§ 7) |
| **Annotation `/F` NoRotate ignored** on a rotated page | ≥ 1 | P1 |
| highlight annotation appearance with an oversized `/BBox` drawn differently from Poppler | 1–2 | P1 (investigate) |
| colour: hue differences at equal lightness (ΔE > 10 on > 1 % of pixels, same L*) — shading / blend-mode / colour-space paths | 7 exact files | P1 (investigate per path) |
| thin strokes lighter *or heavier* than Poppler (hairlines, sub-pixel rule lines) | ≥ 5 | P2 (fidelity, no spec error; see `quality-gate.md`) |
| page size off by > 4 px vs Poppler | 2 (both `/UserUnit` 3, Poppler ignores it — ours is correct) | none |
| JBIG2 images Poppler leaves blank | 4 (ours correct; Poppler fails) | none |

Metric notes: SSIM over whole pages hides glyph-level errors (the
garbled FontMatrix pages scored whole-page SSIM 0.81–0.94); the
runner's `content_ssim` and ink ratio caught them. 82 "size mismatches" are 1-px rounding. The text
LCS ratio is misleading for multi-column pages (Type0 files: LCS median
0.40 but character-multiset F1 median 1.00 — same characters, different
order), so v0.4 adds the multiset score to the runner.

## 3. Writers

**Rewrite** (round trip over 511 files): 418 rewrite, 413 reparse
identically in structure, 384 render identically, 395 extract the same
text; external validity (qpdf) fails on 26 — input-derived in every
case examined (qpdf reports the same on the original); no new qpdf
diagnostic on any rewritten file. Refusals (55): signed documents 27
(by design), catalog entries outside the rewrite profile 20
(`/OCProperties` 14, `/AA` 3, XFA 3), undefined references needed as
indirect objects 8, version / malformed-object 6, encrypted 4.

Gaps the round-trip PASS does not measure:

- **`/OCProperties` refused** — optional content is common (18 files);
  carrying it verbatim is safe (no renumbering hazard beyond the usual
  graph walk). P1, 2 d.
- The annotation check compares a summary (subtype, rect, field name /
  type / value); appearance streams, `/MK`, `/DA`, actions and
  destinations are compared only through rendering. Semantic equality
  of outlines, named destinations, structure tree (`/StructTreeRoot`),
  page labels and embedded files is not checked. P1: extend the
  structural comparison to every reachable catalog entry.
- Size: median ratio 1.00, p90 1.05, max 1.64 — no bloat.

**Incremental save** (new probe, 449 files): 446 saved (3 refused:
encrypted), **446/446** keep the original bytes as an exact prefix,
reparse, show the edit and keep the page count; Poppler renders page 1
identically on 445 (the other: Poppler times out on the *original*
too); qpdf reports no new diagnostic on any (5 apparent ones were a
probe artefact or originals qpdf must already reconstruct). Appended
bytes: median 373, max 1434. No data-integrity defect found. Gaps:
object streams are never written (a new revision of an xref-stream file
uses an xref stream, but objects are always uncompressed), no
`/Info` ↔ XMP synchronisation, no deletion (by design).

## 4. Japanese PDF and CID fonts

109 files carry 359 Type0 fonts. Embedded CID fonts are the norm and
work:

| descendant / program / CMap | files | strict render |
|---|---:|---:|
| CIDFontType2 + TrueType, Identity-H, `ToUnicode` | 60 | 53 (4 recovered, 3 fail on other causes) |
| CIDFontType0 + CFF, Identity-H, `ToUnicode` | 32 | 32 |
| Adobe-Japan1 embedded (H, V, CFF, TrueType) | 6 | 6 |
| embedded CMap stream | 2 | 2 |
| **non-embedded**, Identity ordering | 3 | 0 (correctly refused) |
| **non-embedded**, Adobe-Japan1 with a predefined CMap | 3 | 0 by default; render with `cjk-fallback` |

The 16 files in the `japanese` category: 12 strict, 4 refused (2
predefined CMaps without `cjk-fallback`, 2 non-embedded TrueType with
Japanese names). Missing for practical Japanese use:

1. Predefined CMaps by default: the Adobe-Japan1 set is behind
   `cjk-fallback` (asset size). Proposal: ship the CMaps (small) by
   default, keep the font behind the feature — text extraction and
   CID mapping then work without the fallback face (P1, 1 d).
2. GB1 / CNS1 / Korea1 CMaps and fallback faces (P2; corpus has 4
   files with Chinese/Korean text).
3. Non-embedded TrueType with a Japanese name → the Japan1 fallback
   face, reported (P2, after B above).
4. Text without `ToUnicode` from embedded CID fonts: 8 Type0 files
   extract mostly unresolved codes. Using the embedded font's own
   `cmap` / glyph names is spec-permitted and sound (the program is in
   the file) — unlike guessing from a CID alone (P1, 2 d).

`ToUnicode` is never used to choose glyphs; that rule stays.

Text extraction, all fonts: on 425 strictly extracted files, 51 differ
substantially from `pdftotext` (multiset F1 < 0.9): 13 have their
text only in annotations / form fields (`extract_text` reads page
content only — an option to include widget values is P1), 20 show
codes without `ToUnicode` or usable names, 6 are close but shorter.

## 7. v0.4.0 scope

**P0 — done (2026-10-31).** Fix in `font: glyph outlines through the
program's full FontMatrix`; gate, text multiset scores and category
tables in `quality-gate.md`. The three garbled pages now match Poppler
(content SSIM 0.07 → 0.88, 0.04 → 0.71; ink ratio 3.18 → 1.02, 2.98 →
1.08); no other page in the corpus changed. Original scope: FontMatrix for eexec (read the
cleartext header) and CFF simple fonts (`units_per_em` from the CFF
matrix, as the CID path already does), regression tests with a 2048-unit
font of each kind; a runner gate that flags any exact render whose
ink ratio or content SSIM against Poppler falls outside a band, so this
class of bug fails CI instead of passing as "exact". Done when the
affected corpus files render with content SSIM in the exact renders'
range and the gate is in the nightly.

**P1 — v0.4.0 (≈ 16 d).** In order: runner metrics (multiset text,
per-category rates); NoRotate/NoZoom; colour outliers (one path at a
time, each with a synthetic test); `/OCProperties` in rewrite plus the
semantic round-trip comparison; text from embedded font tables without
`ToUnicode`; annotation/widget text option; CJK CMaps by default;
corpus growth by category (Office, LaTeX, Japanese, OCR scans, large
files). Done when: no exact render outside the gate band; rewrite
refusals limited to signatures, encryption, XFA, version; text multiset
F1 ≥ 0.9 on ≥ 95 % of strict extractions; the corpus report shows
per-category rates for every category in § 5.

**P2 — later.** Everything else in the table. None blocks v0.4.0.

Release risk: P0 changes glyph scale for every non-1000-unit Type 1
font — exactly the intended change, but it moves pixels on files that
currently "pass"; the SSIM-drop check must be read per file, not as a
regression. P1 API additions are additive (`#[non_exhaustive]`).
