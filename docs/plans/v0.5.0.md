# Plan — v0.5.0: verified rewrites, measured robustness

Status: analysis and plan (2026-11-01), on v0.4.0 (`3b88768`), Linux
nightly 41277691417 (Poppler 26.01 with `poppler-data`) and a macOS
run of the same code. Per-file evidence lives in the gitignored
`compat/reports/v050/`; this file carries only aggregates, anonymised
causes and the plan.

## Method

| phase | how |
|---|---|
| Full PASS gap | every `expect: pass` document that is not a Full PASS (87 of 425) — each stage's first error, normalised, merged into one blocker set per document; every blocker classified (unsupported feature, bug, intentional limit / policy, malformed original, witness defect, gate false positive, environment, undetermined) |
| recoverability | a spike branch (not merged) with environment-gated bypasses of each rewrite refusal (the usage-rights bypass *removes* `/Perms`, i.e. option D1 (b)); the compat runner on the 87 documents with no bypass, each bypass alone and all together: which documents then reach a Full PASS and whether their round trip and semantic round trip pass |
| rendering | the runner's per-file approximations, quality classes and technology inventory (font kinds, image filters, shading, scripts); page-1 render time and peak RSS of the CLI on all 511 files |
| text | every `expect: pass` document with text whose page-1 multiset F1 is below 0.9 (37), split by where the missing characters are (page content, annotations, unresolved codes) |
| limits | the documents refused for a resource limit re-rendered with raised limits |

## 4. Decisions (design recorded 2026-11-01; implementation in phases B / C)

Both decisions concern safety and the public API; each is reviewed
independently again before its implementation starts.

### D1 — usage-rights signatures: refuse by default, remove on request

A usage-rights signature (`/Perms /UR`, `/UR3`) grants Reader features;
it does not certify or approve the content. A full rewrite cannot keep
it valid, and keeping it would make the output claim rights it no longer
has. Policy:

- **Default unchanged**: `rewrite` refuses a document with `/Perms /UR`
  or `/UR3` (`Error::SignaturePolicy`, `RewriteOfSignedDocument`), as
  in 0.4.0.
- **Opt-in removal**: only an explicit option removes the usage-rights
  signature; the output is an ordinary, unsigned form.
- **Never removed**: certification (`/Perms /DocMDP`), approval
  signatures (a signature field with `/V`), document timestamps, and any
  document whose usage-rights signature is also reachable as something
  else (below) stay refused with or without the option.
- **Not hidden**: the removal is returned as a structured record (what
  was removed, from where), never only as log text.
- **Verified**: the output must contain no reachable signature value —
  no signature dictionary (`/Type /Sig` or `/DocTimeStamp`, or any
  dictionary with `/ByteRange`) and so none of its `/Contents`, no
  `/Reference` with a `/TransformMethod` — and must pass the graph,
  render and semantic round trips with the removal declared.

`/Perms` is not the only path to a signature, so deleting the `/Perms`
entry alone is not proof of safety. Phase C must check, and refuse when
any is present: the same signature dictionary referenced from a field
(`/V`) or from another object; signature fields and `/Lock` /
`/SV` dictionaries; `/Reference` transform entries (`/DocMDP`,
`/FieldMDP`, `/UR3`); the catalog's `/DSS` (validation data) and
`/Legal`; `/AcroForm /SigFlags` (kept consistent with what remains —
bit 1 "signatures exist" must not claim a removed signature); and
signature content inside XFA packets (XML signatures in `datasets` /
`template`), which a byte-for-byte carry of the packet would keep. The
earlier revisions of an incrementally updated file are not carried by a
full rewrite and need no separate treatment.

API: the 0.4.0 signatures (`rewrite`, `rewrite_with_limits`) keep their
behaviour. The option and the record need an additive entry point — e.g.
`rewrite_with_options(&Document, &RewriteOptions) -> Result<Rewritten,
Error>` with a `#[non_exhaustive]` options builder and a result carrying
the bytes and the removals — checked with `cargo semver-checks` as a
minor-compatible addition. The name and shape are decided in phase C,
not here.

### D2 — executable content: carry, never execute, always report

kasane-pdf never executes JavaScript, and its default rewrite is not a
sanitiser (README). Policy:

- `rewrite` carries executable content verbatim: catalog `/OpenAction`
  (JavaScript included), catalog `/AA`, page / annotation / field `/AA`,
  annotation `/A`, and the `/Names /JavaScript` tree — replacing today's
  refusal of the catalog-level entries, which made the policy
  inconsistent (page-level scripts were already carried).
- Every carried script is **reported** to the caller (what kind, where),
  so none is retained silently; the API documentation states that
  another viewer may run them.
- The semantic round trip (`doc_actions`, `javascript`, phase A) must
  pass on every rewrite that carries them.
- Removing or neutralising scripts is a separate, explicit operation
  (like `remove_document_metadata`), considered after 0.5.0; it is never
  the default rewrite.

The report shares the structured result of D1 (one additive API for
both). The behaviour change (documents refused in 0.4.0 now rewritten)
goes into the CHANGELOG.

## 10. Phase A result (2026-11-01, branch `feat/v050-semantic`)

V1 and V2 implemented in the compatibility runner only (no library
change); measured locally on macOS (nightly configuration), compared
with the macOS run of 0.4.0.

- **No change to any existing measurement**: stage classes, verdicts,
  recovery, approximations, per-page render MAE / SSIM, warnings, every
  round-trip check, `text_char_f1` and its companions are identical on
  all 511 files; Full PASS 338 / 425, robustness 44 / 44, crash /
  timeout 0. The seven earlier semantic categories are identical (class
  and line count on every file).
- **V1** (`docs/plans/semantic-roundtrip.md`): five categories, 427
  rewrites compared — pass 294, not applicable 133, fail / unsupported
  / error 0 (doc_actions 67, metadata 273, viewer preferences 125; XFA
  and JavaScript 0 because 0.4.0 refuses those rewrites). On the
  rewrite spike all 29 XFA forms and 32 JavaScript trees compare and
  pass, and all 39 documents the spike lifts to a Full PASS pass the
  semantic round trip (29 were `unsupported` with the 0.4.0 runner).
  Corpus probes with injected changes: 100 % detected in every
  category, every recompression control passes.
- **V2** (`docs/plans/quality-gate.md`): over the 246 `expect: pass`
  documents with page-1 text on either side (macOS; the Linux nightly
  population is 250), F1 ≥ 0.9 goes from 210 (page text) to 225 (with
  annotation appearances); 20 documents better, 0 worse; CJK 17 / 17
  both. Of the 19 low-F1 documents with annotations, 14 reach ≥ 0.9;
  the rest are appearance differences (a list box without `/AP`, which
  Poppler draws with every option; page text Poppler does not show; a
  note's `/Contents`, which Poppler does not draw; a check box without
  appearance). 4 documents with malformed annotation structures are
  counted, not scored.
- **Found on the way**: X1 (section 3), an engine defect in reading
  updates after a hybrid-reference section — to be fixed on its own
  branch before phase B.
